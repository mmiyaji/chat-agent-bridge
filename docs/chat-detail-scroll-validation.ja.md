# 会話詳細のホイール描画の比較（2026-11-11）

## 状態

利用者がマウスホイールでの体感改善を確認した試作。復元済み会話の詳細カード本文だけを対象に、通常の縦ホイール入力をアニメーションなしの移動にする。他の画面への展開は未実施。

## 調査と変更

- 利用者の症状はマウスホイールで移動している間のみ。停止後のにじみは報告されていない。
- 96 DPIの隔離プロファイルで、スクロール位置を往復させても幅・折り返し・横位置は一定。3組の往復前後の画像はピクセル単位で一致した。恒常的なレイアウトずれは再現していない。
- 標準の移動は停止位置まで約0.2〜0.3秒かけて変化した。表示領域173 DIPで1ノッチ約26 DIP、273 DIPで約41 DIPを確認。
- 標準ScrollViewerのカード内容にホイール処理を付け、親へ伝播する前に処理する。Windowsの行数／ページ単位設定を読み、移動先を物理ピクセルに丸めて `ChangeView(..., disableAnimation: true)` で移動する。
- 修飾キー付き・横方向・マウス以外の入力は処理対象外。カード外の入力、キーボード、スクロールバーは標準の経路を維持する。

## 結果

- Release x64・自己完結型ビルド成功。既存のCsWinRT1032警告あり。
- 96 DPI、表示領域273 DIPの試作で、1ノッチ後の最初の計測（約0.1秒）には41 DIPの移動が完了し、その後の計測値は一定。逆方向も先頭へ戻り、横位置・文字幅・表示領域幅は一定。
- 半ノッチ2回と1ノッチ1回の移動が一致（説明文Y座標496 → 476 → 455）。連続した逆方向入力も開始位置へ戻った。
- 出力: `desktop/artifacts/detail-scroll-731f3f284210470b8cff299c4fd35134/results.json`。一時スクリプト: `.artifacts/check-detail-scroll-preview.ps1`。

利用者から「改善しました」との確認あり。高DPI・実タッチパッド・システムのページ単位設定での実機試験、実チャット／CLIの全件テストは未実施。

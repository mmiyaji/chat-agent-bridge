# Codex / Claude Code の切り替え

同じSlack・Mattermostスレッドで、実行するCLIを切り替えられる。切り替え先では新しいAIセッションを作り、以前のCLIのセッションIDを流用しない。

## 先にPCでCLI接続を登録する

1. 「エージェント設定」でCodexまたはClaude Codeを選び、実行ファイル・モデル・推論・権限を設定する。
2. 「CLIをチェック」で実行ファイルとモデル候補を確認する。
3. 「このCLI接続を登録」を押す。切り替え先のCLIも同様に登録する。

各CLIを1件ずつ登録する。ログイン情報はコピーせず、それぞれのCLIでログインした状態を使う。登録するのは実行ファイル、対応する引数・モード、モデル、推論の強さ、ツール権限、ネットワーク設定、確認したバージョンと日時。未確認のCLI設定や、チャットから渡された実行ファイルのパスは使わない。

「保存したCodex / Claude Codeを読み込む」は、エージェント設定の編集欄への読み込み。アプリ全体の既定値を変更する場合は、読み込み後に通常の設定保存を行う。会話ごとの切り替えは、他の会話やアプリ全体の既定CLIを変更しない。

## PCから切り替える

「履歴と会話」で会話を選択し、「AIエージェントを切り替える」を開く。登録済みの接続から切り替え先を選び、要約を引き継ぐかをチェックで指定して変更する。初期値は引き継ぎなし。

要約ありを選ぶと内容をプレビューできる。実行ファイルや権限は「CLI接続の詳細」で確認できる。切り替え直後は会話一覧に「次回: codex / claude」と表示し、次の依頼で新しいAIセッションを作る。

## チャットから切り替える

会話を開始した本人が、同じスレッドに投稿する。

| コマンド | 動作 |
| --- | --- |
| `!cab agent` | 登録済みCLIと使い方を表示 |
| `!cab agent codex` / `!cab agent claude` | 要約あり・なしの指定方法を表示 |
| `!cab agent codex summary` | Codexへ、要約を引き継いで切り替え |
| `!cab agent claude summary` | Claude Codeへ、要約を引き継いで切り替え |
| `!cab agent codex fresh` | Codexへ、要約なしで切り替え |
| `!cab agent claude fresh` | Claude Codeへ、要約なしで切り替え |

チャットからの切り替えはPCの承認待ちに入り、対象CLI・モデル・権限・作業フォルダー・要約の有無を確認して承認する。自動承認設定でも切り替え自体は自動承認しない。また、切り替え後の最初の依頼にもPCでの承認が必要。

実行中や実行確認中の会話は切り替えられない。チャットからの切り替えで同じ会話に残っていた承認待ち依頼は取り消すため、必要なら再投稿する。

## 引き継ぐ要約と消費量

要約は直近3回までの成功した依頼・最終結果から作る、簡易な抜粋メモ。追加のAI呼び出しによる要約生成は行わない。依頼は各600文字、結果は各1,800文字までとし、全体を8,000文字以内に制限する。省略箇所には印を付ける。CLIの過去の履歴全体や隠れたコンテキストを復元するものではない。

CLI接続を登録する前や、この版で依頼が成功する前の会話にはメモがないため、要約なしで切り替えるか、現在のCLIで一度会話を続けてから切り替える。失敗時のエラー出力はメモに保存しない。

メモはWindowsユーザーのDPAPIで暗号化し、最大200会話分を `conversation-summaries.json` に保存する。切り替え待ちの要約も `sessions.json` 内に暗号化して保存する。次の依頼に1回添付し、切り替え先のネイティブセッションが確定したら待機中の要約を解除する。途中で失敗しても同じセッションの再開時には再添付しない。セッションが確定する前に起動に失敗した場合は、再試行用に要約を保持する。失敗後の実行には、成功するまでPCでの承認が必要。会話を切り離したり作業フォルダーを変更したりすると、その会話の抜粋メモと待機中の要約も削除する。要約生成用の追加トークン消費はないが、転送先CLIではメモが入力トークンとして扱われる。

## セッション・権限の扱い

- チャンネル・スレッド・ユーザー・接続先ごとに分離する。他のユーザーや別スレッドのメモは渡さない。
- 作業フォルダー、会話の承認・結果共有設定、表示名を維持する。作業先は現在の信頼済みフォルダー内に限る。
- モデル・推論・ツール権限・ネットワーク設定は切り替え先の登録済みCLI設定を使う。
- 古いセッションの関連付けは `sessions.json` の `ArchivedBindings` に最大500件保持する。チャットやCLI側の履歴を削除しない。
- 再起動しても切り替え先と承認待ち・要約の状態を保持する。CLI起動に失敗した場合は自動的に元のCLIへ実行を振り替えない。
- 確認中に会話や登録CLIが変更された場合は上書きせず、再試行を案内する。

## 検証方法

Coreテストでプロフィール保存・暗号化・要約の有無・別スコープ・同時変更・承認取り消し・CLI失敗時の保持を確認する。`RemoteOperationsUiE2E.ps1 -AgentSwitchOnly` では、隔離したMattermostプロトコルサーバーとオフラインCLIを使って、実際のWinUI操作で次を確認する。

1. CLIチェック後だけ登録でき、Codex / Claude Codeを保存できる。
2. 成功した会話の抜粋を暗号化し、追加のAIターンを作らない。
3. チャットからの切り替えをPCで承認し、アプリ再起動後も登録・選択・要約を保持する。
4. 自動承認の会話でも切り替え後は再承認し、新しいセッションに要約を1回渡す。続きは新しいセッションで再開する。
5. PCのプレビューで要約本文を確認し、要約なしで元のCLIに切り替える。
6. 許可外ユーザー・別ユーザー・別スレッド・未登録CLIが既存会話を変更できない。

日本語・ダーク、英語・ライトで実施する。実際のSlack・Mattermostへの投稿や有料AIサービスへの依頼、GitHubへの公開は行わない。

```powershell
pwsh -File desktop/RemoteOperationsUiE2E.ps1 -AppDirectory desktop/artifacts/agent-switch-ui-publish -TestAgentDirectory desktop/artifacts/agent-switch-testagent -Language ja -AgentSwitchOnly
```

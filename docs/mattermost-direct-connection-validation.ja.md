# Mattermost直接接続の検証（2026-10-19）

`v0.1.0-preview.3`（アプリ `0.1.0.2`）で、Mattermost専用の「プロキシを使わず直接接続」を追加した。接続設定と初回ウィザードで選び、保存・再接続すると適用する。既存設定で項目がない場合はオフ（システムのプロキシ設定を使用）。

## 適用範囲

- HTTP認証、投稿者の確認、メッセージ返信、接続通知、ユーザー名検索、投稿リンクの確認は `SocketsHttpHandler.UseProxy=false` で直接接続する。
- WebSocketの受信も同じ設定を使い、直接接続時は `ClientWebSocketOptions.Proxy=null` とする。通常時は `HttpClient.DefaultProxy` を使う。
- Slack・CLI・PC全体のプロキシ設定を変更しない。TLS証明書検証、HTTPS制限、トークン保護、許可ユーザー・会話の制限は維持する。
- ユーザー・投稿の検索中に切り替えると、検索を取り消して結果を無効にする。保存済みの接続に途中から新しい経路を混在させず、再接続後に切り替える。

## 検証

- Core 242件、Transports 97件、計339件が成功。保存時のtrueの往復と、既存設定で項目がない場合のfalseも確認。
- 追加した4つの通信試験は、ローカルの拒否プロキシとサーバーを使用。通常HTTPが拒否プロキシへ到達すること、直接HTTP・ユーザー検索がサーバーへ到達すること、通常の投稿確認が拒否されること、WebSocketのプロキシ接続失敗と直接ハンドシェイク成功を確認。プロセス全体のDefaultProxyやOS設定は変更していない。
- 日英の翻訳キー・書式検査、PowerShell構文検査が成功。ポータブルx64と通常MSIXのReleaseビルドは警告0・エラー0。
- 実際のx64 ZIPを展開し、日本語ダーク・英語ライトで各13項目を検証。直接接続の初期値、画面からの保存・再読み込み、幅500/1280 DIPでの表示、その保存設定を使ったMattermost接続、利用者分離、承認・結果共有・停止・通知を含む。ループバックのMattermostプロトコル用フィクスチャと模擬CLIを使用し、実AIは呼び出していない。
- x64・ARM64のZIPは、アーキテクチャ、同梱ランタイム、全ファイルのチェックサム、個人設定・トークン・証明書・テストCLIの混入がないことを検査した。ARM64実機起動と別PC・クリーンWindowsでの起動は未検証。

今回、利用者の社内MattermostサーバーやSWGにはアクセスしていないため、報告された接続エラーの原因がSWGであるとは断定できない。この設定はアプリが使用する明示的・システムプロキシを無効にするもので、透過型ゲートウェイや端末エージェントによる通信経路を変更するものではない。

再現は `desktop/ConversationUiE2E.ps1 -Portable -CheckMattermostProxy -Language ja`（または `en`）で行う。引数のAppDirectoryは `desktop/artifacts` 配下のポータブル展開先を指定する。

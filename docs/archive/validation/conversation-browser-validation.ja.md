# 会話一覧の改善（未公開）

> 過去の検証・実装記録です。記載は当時の状態を示します。現行の手順は[ドキュメント索引](../../README.md)を参照してください。

同じサービス・ユーザーの会話を区別しやすくするため、「履歴と会話」の一覧を変更した。

- 見出しは任意の会話名。未設定なら作業フォルダー名を表示する。
- サービスと利用者、作業先とAI・モデル、最後の実行状態と実行回数、更新日時を一覧へまとめる。内部IDは詳細の折りたたみで確認する。
- 会話名も検索でき、サービス・作業フォルダーで絞り込める。最近更新した順・会話名順・実行回数順を選べる。
- 詳細の鉛筆ボタンから80文字までの名前を設定する。空欄でフォルダー名へ戻せる。更新・再起動・会話継続でも名前を保持し、別ユーザーの会話を変更しない。
- 狭い画面では補助フィルターを折りたたみ、詳細表示中は検索欄を隠す。一覧へ戻る操作と、モデル・承認設定・新規開始の操作を確保する。

会話名はこのアプリ内の表示用であり、チャットのスレッド名を変更しない。本文・結果の保存や、名前を付けるためのAI呼び出しは行わない。表示名を実行設定や認可の判定に使用しない。

実行回数と最終状態は、サービス・チャンネル・スレッド・利用者・CLIセッションIDが一致する記録から集計する。同じ識別情報に複数サーバーが対応する場合は、帰属を決められないため集計を表示しない。過去の別CLIセッションや別ユーザーの記録は加算しない。

名前の保存はファイル単位の排他処理で行い、長いAI実行の終了を待たない。実行終了時に古い会話データが保存されても、直近の表示名を維持する。

## IDに代わる名前の表示

会話一覧の通常表示は、サービス／サイト名、ユーザー名と表示名、チャンネル名を使用する。DM・グループDMは「ダイレクトメッセージ」と表示する。会話名・作業先・AI・実行状態も引き続き表示し、取得した名前は検索にも使用する。内部の利用者・チャンネル・スレッド・セッションIDは詳細の折りたたみに残す。

実行履歴も、対応する保存済み会話から名前を表示する。操作記録は実行IDとサービス・チャンネル・スレッドが一致する実行に関連付ける。古い記録にサーバーの識別情報がなく、複数サーバーに一致する場合は名前を推測しない。名前を取得できない場合は「未取得」と表示し、IDは詳細から確認できる。アクセス制御、実行設定、会話の所有者判定には、名前ではなく従来のIDを使用する。

名前は設定保存先の`chat-identities.json`にキャッシュする。キャッシュには表示名、内部ID、サーバーのハッシュ、取得日時とキャッシュ管理情報を保存し、トークン・会話本文・API応答全体は保存しない。メールアドレスの専用項目は取得・保存しない。画面はキャッシュを先に表示し、設定済みのトークンで必要な名前をバックグラウンド取得する。Mattermostは設定した接続先と会話のサーバーハッシュが一致する場合だけ通信し、直接接続設定をMattermostにのみ適用する。リダイレクトには認証情報を送らない。

ユーザー・チャンネル単位で取得をまとめ、成功は24時間、失敗は5分キャッシュする。1回の取得は40リクエスト・10秒までに制限し、接続不能時も保存済みの名前を残す。権限不足の場合も追加の認可は自動で行わない。Mattermostのサイト表示はクライアント設定APIの`SiteName`を使用し、取得できない場合は保存済みの名前・接続先ホスト名を使用する。サイト名は同一サーバーの会話で共有し、サイト名だけが変わってもチャンネルを再取得しない。

検証には既存の42会話・51実行に表示名キャッシュと操作記録を追加する。サイト・チャンネル・ユーザー名の表示と検索、通常一覧にIDが出ないこと、実行と操作記録への名前の対応を確認する。実行例の`AppDirectory`には、この変更をビルドした`desktop/artifacts/history-names-final-publish`を指定する。

- 通信側テスト148件成功。新規の名前取得テスト11件には、キャッシュと破損ファイル、別サーバー、レスポンスID不一致、リダイレクト、プロキシ設定、DM、古い名前の維持、Slack接続先変更、429、中断後の再利用、件数制限、並行保存を含む。
- 新規一覧UIテストは日・ダーク／英・ライトで各6項目成功。1280×800と500×600でスクリーンショットも確認した。最終通信実装のビルドでも日本語6項目の再実行が成功した。
- 既存の会話操作・再接続テスト13項目成功。最初の実行はリサイズ直後にUI Automationが`stale_element`を返して終了した。同じビルド・同じスクリプトの再実行は全項目成功し、失敗時の画像でも対象ボタンは画面内に表示されていた。テストの期待条件は変更していない。

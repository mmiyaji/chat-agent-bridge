# チャット接続の設定反映と復旧の確認

> 過去の検証・実装記録です。記載は当時の状態を示します。現行の手順は[ドキュメント索引](../../README.md)を参照してください。

2026-10-23。別ブランチでの修正・ローカル検証。公開は行わない。

## 原因と変更

| ケース | 確認した挙動・変更 |
|---|---|
| 追記モード、モデル、承認などの設定変更 | 接続開始時の実行設定と現在の設定を比較し、以後の投稿を無言で除外していた。接続の同一性と、依頼ごとの実行設定を分離し、新しい投稿に現在の設定を使用する。 |
| 許可ユーザー・Slackの許可チャンネル・許可スレッドの変更 | 通信層にも接続時のフィルターが残っていた。現在のフィルターを反映し、アプリ側でも保存済みの権限を再確認する。 |
| サーバー、Mattermostチャンネル、トークン、プロキシの変更 | 古い接続で受信し続けないよう切断し、再接続が必要な理由を表示する。Slackに関係しないMattermost設定の変更ではSlackを切断しない。 |
| 一時的なソケット切断 | 既存の自動再接続を維持。サイドバーも接続処理中→受信可能に追従する。切断中の投稿がサーバーから再配信される保証はなく、復旧時に再投稿の案内を表示する。 |
| テキスト以外・上限を超えるWebSocketフレーム | 手動での再接続が必要になる例外経路を、自動再接続の対象に変更する。受信サイズ制限は維持する。 |
| Mattermost投稿者の確認APIの一時エラー | 投稿を受信済みにした後、投稿者確認の一時エラーで依頼を失う経路があった。429・5xx・ネットワークエラー等について回数を制限して再試行する。本人確認に失敗した依頼は実行しない。 |
| 更新準備で切断した後に処理が中止・失敗 | UIだけ復帰して接続が戻らなかった。元々接続しており、保存された接続先が変わっていない場合だけ接続を復元する。元々未接続なら接続しない。通知用セットアップにも同じ中止処理を適用する。 |

## 維持する安全性

- 受信済み・実行中の依頼の権限、信頼フォルダー、実行設定の再確認は維持する。変更前の依頼が中断・再承認・再投稿を必要とする場合がある。
- 初回承認は実行設定の指紋に結び付けるため、設定変更後に再承認が必要になる場合がある。再接続が不要になることと、自動承認の許可は別である。
- 接続時の認証失敗、許可設定を読み込めない状態、明示的な切断・終了・データ保守では実行を停止する。再接続でアクセス制御を回避しない。
- 既存会話のCLI実行方式や実行ファイル自体が変わる場合は、既存セッションの互換性確認を維持する。

## 検証

- 接続の同一性、会話承認、追記、アクセス制御の関連テスト50件、通信層の全199件が成功。
- 隔離したループバックMattermost互換サーバーと自己完結したオフラインCLIで、実際のWinUI画面から追記モードを保存。同じ接続のまま既存スレッドの返信が `turn/steer` として受理され、結果が返信されることを確認。
- 同じ画面で、一時切断後の復旧、接続状態からチャット受信への移動、手動切断、更新準備中止時の復元、未接続状態を勝手に接続しないことを確認。
- 通常の配布構成でも、接続先変更による切断と理由の表示、サイドバーの接続中・エラー表示を英語／ライト、日本語／ダーク、最小幅で確認。検証専用の復旧ボタンが配布構成に含まれないことも確認。
- 更新案内の集約、ダウンロード失敗・再試行・再起動確認を日英・ライト／ダーク・最小幅で確認。更新バッジは青い円とWindows Fluentのダウンロード記号に変更。
- GUI検証の初回は検証用CLIのフォルダー形式、次にPCの `DOTNET_ROOT` とフレームワーク依存の検証用CLIの組み合わせが原因で停止した。自己完結版を使用する検査を追加した。また、全アプリのUIA探索による待機を対象アプリのウィンドウ内の探索へ修正し、保持した同じセッションから残りの検証を完了した。

実サービスの社内Mattermostや利用者のAI認証・会話には投稿していない。

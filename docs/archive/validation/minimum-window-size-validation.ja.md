# ウィンドウの最小サイズ（2026-10-20）

> 過去の検証・実装記録です。記載は当時の状態を示します。現行の手順は[ドキュメント索引](../../README.md)を参照してください。

最小サイズを幅500×高さ600 DIPにしました。既存の幅500 DIP向けの折り返しとナビゲーションを維持し、極端な縮小で内容と操作ボタンが表示できなくなることを防ぎます。

Windows App SDKの[OverlappedPresenterの最小サイズ指定](https://learn.microsoft.com/en-us/windows/apps/develop/ui/manage-app-windows#modify-an-overlappedpresenter)を使います。モニターのDPIに応じたピクセル数を設定し、XamlRootの変更時も値を確認します。値が変わった場合だけ再設定し、終了時にイベント購読を解除します。

Releaseのx64ポータブル構成をビルドし、専用の未設定データで次を確認しました。

- 日本語／英語×ライト／ダークの4条件で成功。
- Windowsの `WM_GETMINMAXINFO` が最小追跡サイズ500×600を返すことを確認（このPCの表示倍率100%）。
- 最小サイズで初期設定ガイドのタイトル、戻る、次へ、後で設定が見切れず、全般への移動とメニュー開閉ができることを確認。
- 最大化、最小化、復元ができ、復元後も最小サイズが保持されることを確認。
- 代表スクリーンショットと差分を確認し、問題なし。異なるDPIのモニター間の移動は実機検証していません。

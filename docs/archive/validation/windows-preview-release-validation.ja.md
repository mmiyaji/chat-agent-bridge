# Windowsプレビュー配布の検証（2026-10-19）

> 過去の検証・実装記録です。記載は当時の状態を示します。現行の手順は[ドキュメント索引](../../README.md)を参照してください。

配布タグは `v0.1.0-preview.1`、MSIXのバージョンは `0.1.0.0`。x64とARM64をそれぞれ自己完結型で発行し、署名・タイムスタンプを付けたMSIXをZIPへ格納する。配布用identityは `ChatAgentBridge.WinUI.Preview` とし、開発用identityや通常利用の設定を書き換えない。

## 確認結果

- x64 Releaseビルド：警告0、エラー0。Core 240件、Transports 93件が成功。
- 両アーキテクチャのMSIX発行・署名、ZIPの全ファイルのSHA-256、identity・バージョン・アーキテクチャ・署名者の一致を検証。
- .NETの `hostfxr.dll` / `coreclr.dll` とWinUIの `Microsoft.UI.Xaml.dll` を同梱し、外部フレームワークの `PackageDependency` がないことを確認。
- ZIPの内容をMSIX・公開CER・インストールスクリプト・日英の説明・チェックサムの6ファイルに限定。MSIX内にも個人設定、会話履歴、接続トークン用ファイル、秘密鍵、テスト用CLI、入れ子の開発用AppX配置がないことを検査。
- Windows PowerShell 5.1で、証明書ストアを変更せず `Install.ps1 -ValidateOnly` が成功。
- MSIXのアイコンを改変し、外側のチェックサムを再計算したケースも署名検査で拒否。
- x64の配布MSIXから取り出した実際のペイロードを開発用登録で起動し、新しい専用保存先で初回ウィザードを目視確認。

## 検証範囲と配布時の条件

別の物理PC、ARM64実機、開発者ツールのないクリーンWindows環境では未検証。x64の起動確認はこのPCでの開発用登録であり、別PCでの署名済みMSIXインストールの実測ではない。

自己署名プレビューのため、別PCでは公開CERをローカルコンピューターの「信頼されたユーザー」へ登録する管理者操作が必要。インストーラーが証明書を自動で信頼したり、管理者へ自動昇格したりすることはない。Microsoft Storeが署名した製品版ではない。

エージェントCLIとそのログイン、Slack / Mattermostの接続設定は、利用するPCで別途設定する。ZIPは単独EXEを展開して起動する形式ではなく、同梱MSIXをインストールする形式。詳細は同梱の `README.ja.txt` を参照。

## 日本語のSlack返信

前の接続試験で使ったオフラインCLIの標準入出力にUTF-8を明示した。日本語・絵文字のecho、Claude形式の結果、app-server形式の実プロセステストが成功し、コードページ932でも確認した。実際のSlackスレッドでも、日本語の会話継続と自動返信が文字化けせずに届くことを確認した。実際のClaude CLIの動作を模擬CLIの成功と混同しない。

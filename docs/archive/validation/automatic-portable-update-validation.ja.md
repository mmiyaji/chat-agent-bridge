# ポータブル版の自動更新確認とサイドバー表示（2026-10-21）

> 過去の検証・実装記録です。記載は当時の状態を示します。現行の手順は[ドキュメント索引](../../README.md)を参照してください。

## 動作

「情報 → ポータブル版の更新」の「定期的に更新を確認する」で自動確認を切り替えます。初期値はオンです。起動時に一度、その後もアプリが稼働している間に定期的に確認します。トレイ常駐中も続き、完全終了すると停止します。画面には具体的な確認間隔を表示しません。

起動時は画面の描画後に確認します。同じ起動中に利用者が先に手動確認を済ませた場合、その確認を起動時の分として扱い、重複した問い合わせを避けます。オフの場合は起動時にも定期確認を行わず、手動の「更新を確認」だけを利用できます。

更新がある場合、「情報」の隣に24 DIPの丸付きダウンロード矢印を表示します。標準InfoBadgeの注意色を使い、通常表示とアイコンだけのメニューの両方に表示します。ツールチップと読み上げ名には更新先バージョンも含めます。情報画面を開くだけではマークを消しません。

手動確認の隣に「更新内容を見る」を置き、更新候補があるときはそのタグのGitHub Releaseページ、ないときは同じリポジトリのリリース一覧を開きます。保存された候補のリンクも、固定されたGitHubリポジトリ・バージョン・アーキテクチャ・ハッシュ・サイズの条件で検証します。

自動確認は候補の取得だけを行います。ダウンロード・ファイル置換・再起動は利用者の操作が必要です。ダウンロード済みの更新は定期確認で破棄せず、通信失敗でも既知の更新候補と表示を保ちます。

## 保存とエラー

設定と確認日時、更新候補は `portable-update.json` に保存します。通常の接続設定とは別ファイルで、エージェント設定の保存によって上書きされません。設定の書き込みは直列化し、保存中はチェックボックスを無効にします。保存できなかった場合は以前のチェック状態へ戻し、その場にエラーを表示します。

更新候補は再起動直後にもキャッシュから表示できます。その後、起動時の確認結果に合わせて表示を更新します。自動確認をオフにするだけでは既知の候補を消しません。更新の取り下げや更新済みの版が確認された場合はマークを消します。

## 確認方法

通常の利用設定やチャット接続を使わず、[ローカル更新試験](../../portable-update-tryout.ja.md)の専用配置と更新ファイルを利用します。

```powershell
pwsh -NoProfile -File desktop/AutomaticUpdateUiE2E.ps1 -AppDirectory <更新試験用のpublish先> -TestArchive <試験用の旧版ZIP> -UpdateArchive <更新先ZIP>
```

日本語／英語×ライト／ダークの4条件、幅1160・500 DIPで、次を確認し、すべて成功しました。

- 起動時の自動検出、情報以外の画面での更新マーク、狭いサイドバーのアイコン表示。
- 更新確認とReleaseリンクの見切れ・重なり、候補のタグに対応するリンク先。
- オフの保存と再起動後の保持、オフ時に確認しないこと、手動確認による候補とマークの更新、オンへの復帰。
- 候補キャッシュの再起動後の復元、保存失敗時のチェック状態の復旧。
- 自動確認に失敗しても候補と表示が残ること、直前に確認済みでも新しい起動では再確認すること。

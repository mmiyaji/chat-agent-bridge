# 類似アプリを参考にした運用画面の改善

> 過去の検証・実装記録です。記載は当時の状態を示します。現行の手順は[ドキュメント索引](../../README.md)を参照してください。

調査日: 2026-10-02。Web管理画面とWindows EXEの構成を維持し、チャットはSlackとMattermostに限定する。

## 参考にした設計

以下の公開READMEに記載された操作・設計を参考に、既存のAPIと画面上に独自実装した。外部ソースコードや依存ライブラリの取り込みは行っていない。

| 参考 | 採用した考え方 | このプロジェクトでの実装 |
| --- | --- | --- |
| [Agent Connect](https://github.com/Capsbharg/agent-connect) | 初回設定と接続診断を分かりやすくする | 概要画面に、作業範囲・エージェント接続・チャット接続の次の手順を表示。状態取得失敗時は利用可能と判定しない |
| [nariakiiwatani/claude-slack-bridge](https://github.com/nariakiiwatani/claude-slack-bridge) | セッションを一覧で把握する | 状態・Slack/Mattermost・検索の組み合わせで絞り込み、表示件数と該当なしの案内を表示 |
| [OpenCode Chat Bridge](https://github.com/ominiverdi/opencode-chat-bridge) | チャットごとに分離した会話と継続的な状態表示 | 自動更新後にも絞り込みを再適用。作業フォルダーと元の依頼文も検索対象にする |
| [Claude Code Telegram Bridge](https://github.com/rsprowler/claude-code-telegram-bridge) | 途中質問・承認・実行履歴を見えるようにする | ネイティブ要求がある会話を承認待ち／回答待ちとして表示。要求カードに有効期限、会話の詳細に直近の実行結果・エラーを表示 |

## 操作

1. 概要画面の案内に従い、接続と設定を確認する。
2. 会話セッションで状態、チャット、検索語を指定する。検索語には作業フォルダーも使える。
3. セッションIDのボタンから実行履歴を開く。履歴は開いた時点の情報で、更新するには開き直す。
4. 承認・途中質問への返信は、要求が届いた元のチャットスレッドで行う。

実行履歴は既存APIの上限である直近20件を表示する。外部から届いた依頼文・結果・エラーはHTMLとして実行しない。

## 検証

- 型チェックと既存の単体・統合テスト。
- Edgeのブラウザーテスト: 接続案内、複合フィルターの更新後保持、該当なし、回答待ち、履歴内のHTML文字列、存在しないセッション。
- `npm run package:exe` と `npm run test:exe`: 生成したEXEを別フォルダーへコピーし、Node/npm/エージェントCLIのないPATHで起動、設定保存、再起動を確認する。

常駐トレイ、インストーラー、自動更新、資格情報の暗号化は今回の変更対象に含めない。

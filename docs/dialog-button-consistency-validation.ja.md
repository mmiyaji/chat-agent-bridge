# ダイアログのボタン配置統一（2026-10-20）

## 配置のルール

日本語・英語の画面では、ダイアログ下部をWinUI標準の `ContentDialog` に揃えます。

| 役割 | 配置とAPI |
| --- | --- |
| 実行・保存・送信などの操作 | 左側の `PrimaryButton` |
| 第2の操作（終了確認の一度だけのトレイ格納など） | 中央の `SecondaryButton` |
| キャンセル・閉じる・後で・拒否・現在の値を維持 | 最も右側の `CloseButton` |
| ウィザードの戻る／次へ | 左下の戻る、右下の次へを維持 |

終了・削除・権限の承認などの確認では、安全に閉じる操作を既定にします。会話名の編集で保存を既定にしている箇所は、そのまま維持します。ボタンの色や既定操作と、左右の並びは別の判断です。

今後ダイアログを追加する場合も、この3種類の標準ボタンを使い、内容欄に独自のキャンセル用フッターを置かない方針です。

## 変更内容

- 規約・プライバシーポリシー：内容欄の独自の横幅いっぱいの閉じるボタンを廃止し、固定フッターの右端に標準の「閉じる」を配置しました。本文はスクロールして読めます。
- 表示言語の再起動確認：「後で」を第2操作から標準の閉じる操作へ変更しました。保存した言語を保持して再起動を延期する意味は同じです。
- 更新内容：標準の「閉じる」を既定にしました。
- 手動料金の削除確認：選択したライト／ダークテーマを明示的に適用し、画面確認用の識別子を追加しました。
- 既存のUIテストは標準の閉じるボタンの識別子へ追従させました。

アプリ内のダイアログ生成箇所18件を確認し、取り消し・保留操作が標準の `CloseButton` に揃っていることを確認しました。ウィザードの配置を定義するXAMLは変更していません。

## 確認方法と範囲

`pwsh -NoProfile -File desktop/DialogConsistencyUiE2E.ps1 -AppDirectory <desktop/artifacts内のポータブル配置先>` で実行します。

日英それぞれでライト／ダークを使い、幅1160・500 DIPで表示と操作を確認します。規約、プライバシーポリシー、実行確認、更新内容、情報画面からの終了、×での終了、言語の再起動確認、会話名・モデル・承認方針・エージェントの変更、会話の切り離し、手動料金の削除を対象にしています。

各ダイアログで、ボタンの順序、画面外へのはみ出し、重なり、閉じる操作を確認し、スクリーンショットも保存します。会話の編集・削除や料金の削除を取り消した際に保存内容が維持されること、AI実行が開始されないことも確認します。ウィザードの戻る／次への配置に加え、実際に2ページ目へ進んで戻れることを確認します。

専用のローカル設定と模擬会話を使用します。通常利用の設定や認証情報、Slack／Mattermostへの投稿、AIエージェントの実行は使用しません。AI内部から呼ばれる承認・追加入力や実更新の確認画面はコードの配置確認対象であり、今回の実画面テストでは呼び出していません。

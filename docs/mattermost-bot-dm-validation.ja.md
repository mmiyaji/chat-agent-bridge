# Mattermost Bot DM・メンションの検証（2026-10-19）

`v0.1.0-preview.3` まではMattermostの先頭 `!cab` だけを受信対象としており、BotとのDMでも `@Bot名 依頼内容` は無視していた。`v0.1.0-preview.4`（アプリ `0.1.0.3`）で、接続したアカウントへの先頭メンションにも対応する。

## 受信条件

- トークンで認証した `/api/v4/users/me` のusernameを使用する。Bot名を手入力して照合する設定は不要。
- `@cc-agent-bot 依頼内容` のように、先頭の完全なユーザー名と空白、その後の依頼内容が必要。別Bot名・似た名前・本文途中のメンション・本文なしは受け付けない。
- 従来の `!cab 依頼内容` も維持する。メンションの後に `!cab` を重ねた場合も、そのコマンド部分だけを取り除く。
- DMも設定したチャンネルIDだけが対象。許可ユーザーには依頼を送る本人の内部ユーザーIDを入れる。ユーザー名検索で追加して保存・再接続する。メンションがあっても、許可していないユーザー・チャンネル・会話からの依頼、Bot自身・他Bot・Webhookの投稿は除外する。
- 同じスレッドで続ける場合も、Mattermostではメンションまたは `!cab` を明示する。通常のDM本文をすべて取り込む変更はしていない。

## 検証

- 先頭メンションの構文・境界と既存フィルターの追加試験を含む通信テスト101件が成功。実Mattermost試験を有効にして実行し、既存の通常チャンネル試験と新しいBot DM試験も実際に通った。
- Dockerの専用Mattermost（localhost:8070）に一時的なBotアカウントとBotアクセストークンを作成し、別の個人アカウントとの専用DMで実通信を確認。メンション、日本語・絵文字、元スレッドへの継続、同じDMスレッドへの返信、`!cab` の互換性、再接続、Bot自身・無効なメンション・対象外DMなどの除外を確認した。
- 試験用Botのトークン失効とBot無効化のAPI成功を確認し、一時Botが有効一覧に残っていないことも確認した。実行中の専用サーバーで一時的に有効にしたBot作成・アクセストークンの設定は、両方とも元のfalseに復元した。社内サーバーや通常利用中のアプリ設定は変更していない。
- x64 ZIPを実際に展開し、日本語ダークでは `-MattermostMentions` で先頭メンションを使い、英語ライトでは従来の `!cab` を使って、会話・承認・結果共有・停止・通知・直接接続設定の保存と再読込を各13項目確認。幅500/1280 DIPで設定説明の表示を確認した。
- ポータブルx64および通常MSIXのReleaseビルドは警告0・エラー0。日英リソース、PowerShell構文、Nodeフィクスチャ構文、差分の空白検査も成功。
- x64・ARM64の配布ZIPについてアーキテクチャ、ランタイム、全ファイルのSHA-256、個人設定・トークン・証明書の非混入を確認した。ARM64実機・別PC・クリーンWindowsでは未検証。

UI試験は `desktop/ConversationUiE2E.ps1 -Portable -CheckMattermostProxy -MattermostMentions -Language ja` で再現する。AppDirectoryは `desktop/artifacts` 配下の展開済みペイロードを指定する。実Mattermost試験は `CAB_ENABLE_NATIVE_MATTERMOST_E2E=1` と `CAB_NATIVE_MATTERMOST_STATE_FILE` を指定し、専用サーバーでBot作成・トークン発行を利用可能にして `MattermostBotDmIntegrationTests` を実行する。状態ファイル・トークン・試験証跡はGitとZIPの対象外。

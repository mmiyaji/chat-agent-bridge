# Docker Mattermostの履歴表示名・キャッシュ検証

検証日：2026-10-19（日本時間）。公開・リリースアップロードは行っていない。

## 環境と範囲

- 起動済みの専用コンテナー`cab-winui-e2e`、`http://127.0.0.1:8070`を使用。
- 管理者ではない`system_user`のAPIトークンで、別のメンバーと参加チャンネルの情報を取得した。Bot作成はサーバーで無効だったため、Bot用のサーバー設定は変更せず、一般ユーザー権限で検証した。
- 独立したポータブルアプリとデータフォルダーを使用した。既存アプリの停止や設定変更、AIの起動、チャットへの投稿は行っていない。
- 呼び出し回数はローカルの読み取り専用中継で測定した。中継先は専用Dockerサーバーに固定し、ユーザー・チャンネル・クライアント設定のGETだけを許可する。オフライン時の試行も数え、認証ヘッダーや応答本文は記録しない。

## 発見と修正

従来はサイト名の代わりにホスト名を表示していた。`GET /api/v4/config/client?format=old`から`SiteName`だけを取得し、サーバー単位でキャッシュするよう修正した。古いチャンネルキャッシュにホスト名が入っていても、新しいサイト名を優先する。サイト名が変わった場合もチャンネル・ユーザー情報を余分に再取得しない。

クライアント設定APIが利用できない場合は、保存済みのサイト名を維持し、初回ならホスト名で代用する。設定APIの全内容は保存しない。

## 実機結果：4項目成功

| 確認 | 結果 |
|---|---|
| 空のキャッシュからの取得 | `@cab-winui-member`、`CAB WinUI Channel`、設定されたサイト名`Mattermost`を表示。名前で検索でき、通常の一覧に内部IDは出ない |
| 初回の通信 | サイト・ユーザー・チャンネルを各1回、合計3 GET。すべて実際のDocker APIの200応答 |
| 保存内容 | サーバーのハッシュで分離した3件のキャッシュ。設定トークンはDPAPI保護、キャッシュにトークン・メール専用項目・本文・API応答全体なし |
| オフラインで再起動・更新 | 名前を表示。取得リクエストは試行を含め0回。3件の取得日時も不変 |
| ユーザーのキャッシュだけを期限切れ | 当該ユーザーのGETが1回のみ。ユーザーの取得日時を更新し、チャンネル・サイトの取得日時は維持 |

結果と画面記録は`desktop/artifacts/history-names-real-6eda4d30db304d11929552b29562f839/`にローカル保存した。テストが起動したアプリと中継プロセスは終了済み。

通信テストは150件成功。サイト名の取得・変更・取得失敗時の保持・429後の再起動も追加検証した。回帰テスト中、Slackの無効化イベントを送信直後に模擬サーバーがソケットを破棄し、受信が失われる競合も見つかった。テスト用ソケットを検証終了まで維持して安定させた。Slack製品コードは変更していない。

既存のSlackサイト切り替えテストでも一度キャッシュ名が空になる失敗があった。個別実行と同じバイナリーでの全150件の再実行は成功した。この事象はDocker実機テストでは発生しなかった。

## 再実行

```powershell
pwsh -NoProfile -File desktop/MattermostHistoryNamesUiE2E.ps1 `
  -AppDirectory desktop/artifacts/mattermost-history-real-publish `
  -FixturePath desktop/artifacts/mattermost-history-names-member.json
```

指定する実行ファイルはこの変更を含むポータブルビルドとする。fixtureの`bridgeUser.protectedToken`には同じWindowsユーザーで保護した`dpapi:`値を指定できる。トークンをチャット・コマンド引数・コミットへ含めない。既存のローカルMattermostテストfixtureの`bridgeUser.token`にも対応する。

実際の会話やCLIセッションを作成するテストではなく、実APIで解決した名前の表示と保存を確認するテストである。

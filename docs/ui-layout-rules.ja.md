# UIレイアウトのルール（アライメント）

WinUI 版の画面で、端や列を揃えるためのルールです。画面を追加・変更するときに守り、迷ったら既存の実装（括弧内）に合わせてください。

## ページ全体

- ページの左右の余白は、通常24 DIP、幅720 DIP以下では16 DIPにする（`MainPage.UpdatePageInset`）。
- 設定系のページ（全般・手動で実行・エージェント設定・チャット設定・情報）は、本文の最大幅を1040 DIPにする。チャットと履歴は全幅を使う（`MainPage.PageContentMaxWidth`）。
- ページ上部の通知バナー（更新のお知らせ・実行状態）は、そのページの本文と同じ幅にする。本文より右に伸ばさない。
- ページタイトルの大きさは、ウィンドウ幅で変えない。全ページで `TitleTextBlockStyle` を使う。

## カードと内側の余白

- 背景のあるカードやペインの中身は、上下左右に同じ余白を取る。設定の詳細ペインは、左ナビ表示でも上部タブ表示でも16 DIP にする（`SettingsDetailContentMargin`）。中身をカードの端に接させない。
- カードの外に置く要素（リンク・説明文）は、カードの端か、上の文字の左端に揃える。

## 見出しの階層

- 階層は「ページタイトル（Title）→ 範囲の見出し（`SettingsScopeTitleStyle`）→ セクション見出し（`SettingsSectionHeaderStyle`）」の順にする。
- 下の階層の見出しを、上の階層より大きくしない。Expander やカードの中の小見出しにも `SettingsSectionHeaderStyle` を使い、`SubtitleTextBlockStyle` は使わない。

## ラベルと入力欄の列

- 「ラベル列＋入力列」の行は、ラベル列190 DIP・列間10 DIPにし、入力列の開始位置をそろえる（`AgentProfileEditorControl`）。
- 入力に付属する要素（ボタン行・候補の選択欄・補足の説明文）は、ラベル列ではなく入力列から始める。狭い幅でラベルを上に置くレイアウトのときは、左端から始める。
- 読み取り専用の値を入力欄と同じ列に表示するときは、左に11 DIPのパディングを付け、入力欄の中の文字と同じ位置にする。

## リンクとボタン

- 1行に単独で置く HyperlinkButton には `LeadingLinkButtonStyle` を使い、文字を上の文字の左端に揃える。文中や横並びの2つ目以降には使わない。
- ピボットやセレクターバーのタブは、最初のタブの文字をページタイトルの左端に揃える。既定の内側の余白は、負のマージンで打ち消す（`HistoryPage`）。
- 表の操作列は、見出しとボタンを右揃えにし、上にある追加ボタンの右端に揃える。
- 同じ種類のボタン（各サービスへの接続など）は1つのグループにまとめる。狭い幅で折り返したとき、種類の違うボタンが同じ行に混ざらないようにする。

## ウィザード

- 見出し・スクロールする本文・フッターの左右の端を揃える。本文の左8 DIP（必須項目の赤枠のため）と右12 DIP（スクロールバーのため）を、見出しとフッターにも付ける。
- 必須項目の赤枠（`FieldHighlight`）を表示しても、周りの要素の位置を動かさない。

## 確認のしかた

- 変更した画面は、幅1440・1000・700・520でスクリーンショットを撮って確認する。ウィザードは通常幅と狭い幅に加え、必須項目のエラー表示も撮る。
- 揃っているか判断しにくいときは、スクリーンショットに縦のガイド線を引き、ピクセル座標で比べる。
- スクリーンショットの撮影と確認は、AGENTS.md のルールに従って低コストのモデルに任せてよい。

# データと復旧

全般 →「データと復旧」から操作する。保存先は画面で確認できる。

## バックアップと復元

バックアップ対象はエージェント種別・CLIの場所・モデル・推論の強さ・作業フォルダー・
Mattermost接続先・チャットのチャンネル設定。JSON形式で、保存先は利用者が選ぶ。
作業パス・サーバー名・チャンネルIDを含むため、ファイルは非公開で保管する。

接続トークン、任意のCLI引数、許可ユーザー・スレッド、信頼フォルダー一覧、承認記録、
自動接続・自動実行・自動共有、外観、Windows自動起動設定は引き継がない。
CLI引数は各プロバイダーの既定値になる。独自CLIの引数は再設定が必要。

復元前にCLI・作業フォルダーを表示する。作業フォルダーは「信頼して復元する」を
明示的に選んだ場合だけ復元し、それ以外は未設定にする。復元時にはチャットを切断し、
通知の古い承認操作を無効化する。トークンを入力し、許可ユーザー等を再設定してから再接続する。
実行中・承認待ち・設定保存中には復元しない。

復元前の元ファイルは同じPCのデータフォルダーに
`settings-original-before-restore.json` として保管する。
これは配布・移行用バックアップとは異なり、DPAPI保護済みのトークン等も含む元ファイルのコピー。
共有や診断情報への添付はしない。設定が壊れていても元ファイルを残して復元できる。

## データの削除

対象を選択し、確認してから削除する。対象は次の4種類。

- 実行・操作履歴（それぞれ直近500件）
- 会話の対応付け・引継ぎメモ・添付承認・チャット名キャッシュ
- 日別・モデル別の利用実績集計
- 通知の診断ログ（アプリが管理する既知のファイルのみ）

実行・操作履歴だけを削除した場合、利用実績の集計は残る。
集計も削除した場合、残っている詳細履歴から自動で集計を再作成しない。
削除後も接続は停止したままになる。作業ファイル、CLI自身の会話履歴、
チャットサービス上の投稿は削除しない。設定・バックアップもこの操作の対象外。

シンボリックリンクやジャンクションを経由する保存先は、この画面から削除・復元しない。
任意のディレクトリを再帰削除する機能は持たない。

## 診断情報

情報 →「診断・サポート」でシステム・CLI確認・通知登録・更新の状態を確認する。
チャット欄は保存済み設定の状態であり、実際の通信疎通を示すものではない。
テスト通知はAI実行・チャット投稿・依頼の承認を行わない。
通知APIに送信できても、集中モード等でバナーが出ることは保証されないため、送信と画面表示を区別する。

診断レポートは固定された項目だけを生成し、内容をプレビューしてから任意の場所へ保存する。
トークン、依頼・結果本文、作業パス、利用者・チャンネル・スレッド情報、環境変数、
生のCLI出力、生の例外メッセージは書き出さない。自動送信は行わない。

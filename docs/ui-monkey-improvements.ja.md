# UIモンキーテストと改善（2026-10-18）

通常利用の保存先とは別の `--data-dir` を使い、WinUIの7画面を検証しました。実モデルの実行、Slack／Mattermostへの接続・投稿、Windows自動起動の変更、外部リンクの起動は行っていません。

## 見つかった問題と修正

| 問題 | 修正 |
| --- | --- |
| 幅500 DIPでナビゲーションが最小表示になると、メニューボタンが概要の見出しに重なる | NavigationViewの実際の表示モードに応じて上部に48 DIPを確保。Compact／Expandedへ戻ると解除する |
| Codexの操作権限を選択後、「その他のCLI」へ切り替えると、非対応の権限が残り保存できない | その他のCLIはCLI既定へ戻し、アプリ側の権限選択を無効化。CLI自身の設定を使うことを説明する |
| 「操作ごとに確認」を選択後、App Serverをオフにすると非対応のモードが残る | 読み取り・計画のみへ変更し、変更理由を表示。保存済みの有効な承認設定を読み戻す際は変更しない |
| Codexとして認識できない実行ファイルとモデル・権限を組み合わせると、英語の内部例外が出る | 保存前に日本語・英語で実行ファイルの選び直し方を案内。拒否時は保存済み設定を上書きしない |
| その他のCLIではモデル入力欄が無効なのに、直接入力を促す説明がある | CLI自身の設定・起動引数でモデルと推論の強さを指定する説明へ変更する |

Coreの権限・信頼フォルダー・アクセス制限は変更していません。操作権限の調整は、フルアクセス・自動承認への変更を行いません。

## 検証方法

- `MonkeyTest.ps1`：固定シード18743／90211。設定入力、保存・再読み込み、画面遷移、連続遷移、スクロール、サイズ変更に加え、情報ページの4種類のダイアログ、3種類のテーマ、権限・承認・推論の選択を実施します。各シードで全画面と追加項目を先に確認し、長い日本語・絵文字の依頼文も必ず入力します。
- `ResponsiveNavigationUiE2E.ps1`：7画面を幅500→720→1160→500→720 DIP、高さ600 DIPで切り替え、見出しとメニューボタンの重なり、拡大時の余白の復帰を検査します。UI Automationの矩形検査に加えて画像を確認します。
- `ProviderPermissionUiE2E.ps1`：その他のCLIへの切り替え、保存済みApp Server承認設定の再読み込み、App Serverオフ、Claude Codeへの切り替え、認識できない実行ファイルの拒否を確認します。

テスト側も、画面外の入力欄を表示してから操作する、ポップアップ内の選択肢を識別する、空欄を実値で確認する、途中停止を成功扱いしない、という点を改善しました。JSON結果と画像はGit管理外の `desktop/artifacts` に保存します。

## 結果

初回240操作では、権限が非対応のまま残る保存失敗を4回確認しました。同じ問題の再発回数であり、4種類の不具合という意味ではありません。

修正後の240操作では保存失敗の再発はありませんでしたが、テストツールの空欄比較が3件失敗しました。空の値に対して表示名へフォールバックするAPIの仕様を確認し、`Value`プロパティを直接比較する方法に変更しました。この実行結果自体はFAILとして保持しています。

判定修正後は、同じ2シードを各40操作で再実行し、**80操作・943 UIコマンド、失敗0、完了状態PASS**となりました。各シードで7画面・13操作カテゴリ・全ダイアログ・全テーマ・全ポリシー分類を確認し、空欄2フィールドと長い日本語・絵文字の依頼文も検査しました。

日本語36項目・英語36項目の画面幅の検証と、権限切り替えの回帰確認5項目も成功しました。日本語のダーク表示、英語のライト表示の7画面の画像を確認しています。Releaseビルドは警告0・エラー0、日英リソース764項目の整合性検査とPowerShellスクリプトの構文検査も成功しました。

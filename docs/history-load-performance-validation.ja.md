# 履歴とチャット受信箱の負荷検証

Windows 10.0.26300、Core i5-13400F（10コア・16スレッド）、メモリ32 GiBで実施。基準版は1.1.1のローカルx64 Releaseビルド（`23a0770`）。公開コミットとの差分はライセンス一覧のみ。比較ビルドもローカルのx64 Releaseと.NET 10.0.14を使用した。計測はLunaが担当した。

## 条件

- 合成データを専用の `--data-dir` に保存し、各試行でプロセスを起動し直した。OSのファイルキャッシュは消去していない。実チャット、CLIの実行、実利用者のデータは使用していない。
- 最大ケースは保存済み会話5,000件、実行記録500件、操作記録500件、チャット受信箱500件。保存済み会話と受信箱は別の一覧。
- 履歴の初回表示はナビゲーション操作から、期待した件数がUI Automationで読めるまで。検索は5,000件から1,000件への絞り込み、並べ替えは選択が残る条件で名前順に変更した。時間にはUI Automation呼び出しとポーリングを含む。
- 通常計測とCPUサンプリングは別の試行。経過時間は各3回の中央値、CPU時間はプロセス全体の平均。スレッド別CPU時間としては扱わない。

## 上限ケースの結果

| 指標 | 基準版 | 修正版 |
| --- | ---: | ---: |
| 履歴の初回表示 | 413 ms（397–416 ms） | 297 ms（271–419 ms） |
| 履歴表示までのプロセスCPU時間 | 724 ms | 469 ms |
| 5,000件から1,000件への絞り込み | 277 ms | 282 ms |
| 名前順への並べ替え | 216 ms | 220 ms |
| チャット受信箱の初回表示 | 117 ms | 115 ms |
| 操作後のプライベートメモリ | 217 MiB | 212 MiB |
| 並べ替え後も同じ会話行が選択されていた回数 | 0 / 3 | 3 / 3 |

履歴の初回表示の中央値は約28%短縮し、履歴表示までのCPU時間の平均は約35%減った。絞り込みと並べ替えの経過時間には改善を確認できなかった。3回ずつの単一PCでの比較であり、最悪値や他の端末での再現性は評価していない。

実行・操作記録を各500件に固定した小規模ケースでは、履歴の初回表示の中央値は保存済み会話50件で333 msから323 ms、500件で337 msから240 msだった。受信箱はそれぞれ50件、500件。

最大ケースのEventPipe CPUサンプリングは両版とも待機系のスタックが上位を占めた。短い一覧更新区間のホットスポットをサンプル単独で特定できなかったため、変更箇所の根拠はコード上の通知回数と、変更前後の時間計測を合わせて判断した。

## 実行記録と操作記録を増やした場合

保存済み会話と受信箱を各500件に固定し、実行記録と操作記録をそれぞれ50件から500件に増やした。各セルは3回の中央値。

| 実行記録と操作記録の件数 | 履歴の初回表示・基準版 | 履歴の初回表示・修正版 |
| --- | ---: | ---: |
| 各50件 | 302 ms | 234 ms |
| 各500件 | 344 ms | 338 ms |

この計測では、ログが多い条件で履歴の初回表示に時間がかかった。個別タブの表示時間は、実行が基準版168→209 ms、修正版192→167 ms、すべての操作が基準版108→125 ms、修正版116→112 msだった。増減の方向が両版で揃わず、個別タブへの影響は判定できなかった。

## 変更

履歴の会話一覧では、全件追加や大きな並べ替えで多数の変更通知が発生していた。変更が16行以上なら既存の一括更新コレクションを使用し、個別通知を1回のリセットにまとめる。少数の変更や差分がない場合は従来の差分更新を使う。リセット後も、表示対象に残る会話は同じキーで選択を復元する。

5,000件での専用テストではUI Automationの選択状態を確認した。幅1,160の別試行のスクリーンショットでも、並べ替え後の選択行と右の詳細ペインが同じ会話を示した。

既存の `HistoryBrowserUiE2E.ps1` は両版でアクセス許可からの履歴リンクと会話名の確認を通過した。幅500、高さ600の実行表では、行セルをUI Automationで取得できず、両版とも列揃えのアサーションで停止した。

## ローカルの計測記録

作業フォルダーの `.artifacts/history-perf/` に `Measure-History.ps1`、各試行の `results.json`、CPUサンプリングの `.nettrace` を保存した。最大ケースの比較には `baseline-reverse-5000/results.json` と `candidate-5000/results.json` を使った。トレースは `profile-baseline2-5000/` と `candidate-profile-5000/`、詳細ペインのスクリーンショットは `candidate-pane-check-5000/` にある。

# Muse Code CLI Preview 検証メモ

## 対象と結論

Muse Code CLIをChat Agent Bridgeから使うPreview実装の互換性を確認した記録です。対象バイナリは `1.4.14-R7309.1`。公式CLIヘルプ、ローカルのecho実行、保存済みfixtureで引数・出力処理を確認しています。Museサービスへの認証済み依頼や課金が発生する実行は行っていません。Muse Codeの契約・認証状態・サービス応答は未検証です。利用者に購入や課金を求めず、サービス検証は保留します。

| 項目 | 確認結果 |
| --- | --- |
| 基本実行 | `muse exec --json`。JSONL出力を処理する |
| 依頼文 | 標準入力では受け取れない。CABは依頼文を一時ファイルに置き、CLIのprompt-file機能で渡す |
| 継続 | CABが保存したUUIDを `--session-id` に渡す |
| モデル | 手動指定に対応。モデル一覧取得は未対応 |
| 推論設定 | CABからの指定は未対応。CLIの既定設定を使う |
| 権限 | CABでは`inherit`のみ。Muse Code側の承認・サンドボックス方針に従う |
| 実行中の追記 | 未対応。追加依頼はCABのキューで順番に処理する |
| 認証・実サービス | Muse Codeへのログイン・契約上の利用資格・認証済み応答は未検証 |

標準入力に依頼文を渡す方式は使えません。GUIなしの実行で承認が必要な操作は、利用者がその実行中に応答できず保留または失敗する場合があります。Muse Code自身の設定を事前に確認してください。`--disable-approval`、`--yolo`、`--disable-sandbox` をCABが自動付与することはありません。初回設定や必要なアクセスの選択はMuse Code側の説明に従い、権限を一律に広げないでください。

CABの既存の依頼承認・結果共有・添付設定はこのCLI対応によって変更しません。CLIチェックはバージョンと識別を確認するもので、ログイン状態、契約上の利用資格、モデル利用可否、AI実行成功を保証しません。Muse Codeの利用権限と `muse login` はCLI側で別途必要です。課金が必要と案内された場合は今回の検証対象外とし、購入を前提にしません。

PreviewはCAB側の対応の検証段階を示し、Muse Code自体の提供段階を示すものではありません。

## 安全な入力・実行

- 依頼本文はコマンドラインへ載せず、ユーザー専用ACLの一時ファイルで渡す。作業フォルダー内には置かず、リンクを含む作業先は実体パスへ解決し、入力保存先と重なる広い作業先は案内して拒否する。
- 専用leaseで並行実行中の入力を孤児掃除から保護し、終了・失敗・キャンセル後は削除する。残った入力はアプリ起動時と次のMuse実行時に所有者・lease・パスを検証して整理する。
- 許可された会話IDの出力だけを採用し、未完了・異常終了・不正な出力は成功として保存しない。推論本文やツール入力などを出力欄へ流さない。
- 操作の承認待ちを検知した場合はCLIを停止し、固定の案内を表示する。権限の自動緩和やプロジェクトフックの信頼回避は行わない。
- Windowsの版付き実行ファイルを検出しても設定は `muse` のまま保存し、CLI更新後も現在の版を解決する。

## 検証の範囲

- `muse --version` と `muse exec --help` のヘルプ・引数を確認。
- 公式CLIのechoで同じUUIDv7による2ターン継続を確認。設定・セッション保存先は隔離し、APIキーを渡していない。echoは任意モデル別名を受け付けず、実サービスでのモデル変更は未検証。
- オフラインfixtureでは新規・継続・モデル引数変更、異常終了、ID混同、不正JSON、使用量の不正値、承認待ち、キャンセル、並行実行の一時ファイル保護、広い作業先の拒否を確認。
- 日英・ライト／ダークでscope・Preview・∞アイコン・tooltipを確認。検索遷移、モデル手入力、自動検出の適用と安定した `muse` の保持、認証不要のCLIチェックも実画面で確認。狭幅は操作ツールでリサイズできず未確認。
- 初回実装のCoreテストは1567/1567成功、Transportsは295/295成功。Releaseビルド・日英文字列検査・設定Expander検査も成功。
- ビルドと同時に実施した一回のCore実行では既存のプロセス中断テストが失敗した。単独4回と最終の直列全体実行では成功し、原因は確定していない。

公式資料: [Headless and CI](https://dev.meta.ai/docs/muse-code/extending)、[Configuration and context](https://dev.meta.ai/docs/muse-code/configuration)、[Permissions and safety](https://dev.meta.ai/docs/muse-code/permissions)。

## レビュー後の補強

- Museの起動エラーは設定不備・実行ファイル不在・起動用メタデータ不備・アクセス拒否に分け、依頼本文や生の標準エラーを表示しない。
- 承認待ちは既知の待機イベントを明示的に判定する。自動承認済み・無関係なイベント名の部分一致では中断しない。
- 失敗した新規会話のIDは保存しない。既存の会話の保存内容は失敗時にも維持する。
- Kimiは承認の実コマンドを危険度判定へ渡し、取得できない操作は未判定の注意を示す。承認待ちは実行時間の予算から除外するが、ユーザーキャンセルは維持する。
- ACP v1の`session/load`応答ではモード情報が任意のため、省略された場合も要求したモードを明示的に設定し、成功応答を確認してから依頼を送る。[ACP公式セッション仕様](https://github.com/agentclientprotocol/agent-client-protocol/blob/main/docs/protocol/v1/session-setup.mdx)を参照。

### 補強後の検証

- Core全体1577/1577成功（`xUnit.MaxParallelThreads=4`）。Muse/Kimi/危険度判定の関連91件も成功し、その後に起動エラー3分類の追加テストを含む全体実行を行った。
- Windowsの実ジャンクションで通常の作業先が実行でき、一時入力領域の配下へ向く親ジャンクションは拒否されることを確認。起動時整理は孤児だけ削除し、排他leaseを保持する実行中入力は維持する。
- Kimiは模擬ACP子プロセスでモード情報の省略・設定拒否・承認待ちの予算除外・残り予算の維持・承認中キャンセルと子プロセス終了を確認。
- 通常並列の全体実行で、既存の中断テストが終了後の一時ディレクトリ削除に失敗した。プロセス終了のアサーションを残し、後片付けを既存の削除リトライへ揃えた。今回確認できた失敗箇所は後片付けであり、以前の別実行の原因まで断定していない。
- 有料アカウントへのログイン・AIサービス呼び出しは行っていない。画面構成は変更しておらず、今回の日英・テーマ別のUI再撮影は省略した。
- Transports全体295/295成功。x64ポータブル構成のデスクトップReleaseビルドは警告0・エラー0、日英リソース検査と設定Expander検査も成功。

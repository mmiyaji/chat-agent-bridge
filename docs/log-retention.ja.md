# ログと履歴の保持設定

情報ページの「詳細設定」を開くと保持期間と上限を変更できます。期間や容量を減らす場合は、既存データが削除されるため確認を表示します。初期値へ戻す操作だけでは適用せず、適用ボタンで確定します。

| 対象 | 初期値 |
| --- | --- |
| 日別・モデル別の利用統計 | 1,825日 |
| 監査ログ | 365日、1ファイル4MB、最大16ファイル |
| 実行の詳細履歴 | 30日、最大500件 |
| 会話一覧 | 30日、最大500件 |
| Windows通知の診断ログ | 7日、1ファイル128KiB、最大4プロセス分 |

期間内でも件数・容量上限に達すると古い記録から削除します。実行・承認待ちの記録は期限削除から保護し、再起動後も自動再開はしません。実行詳細を削除する前に利用統計へ反映するため、詳細履歴より長く日別集計を残せます。

監査ログは追記型JSONLで保存し、ファイル単位でローテーションします。期限の境界をまたぐファイルは期限より古い記録を一部含む場合があります。画面で読めるのは最新500件です。画面の件数上限と、ディスク上の保持上限は別です。

通知診断は非同期のベストエフォート記録です。負荷や強制終了で一部が残らない場合があります。監査ログとは保存保証が異なります。メモリ上のストレージ診断にはこの設定を適用しません。

設定はデータフォルダーの `log-retention.json` に保存します。設定が破損・読み取り不能の場合は、短い初期値で削除を進めず保持処理を見送ります。適用時の一部清掃に失敗しても、保存済み設定は保持し、画面に再試行待ちを表示します。

保持処理は起動時と定期処理に加え、各ストアの読み書きでも行います。対象はアプリが所有する決まったファイル名に限定し、リンク先や作業フォルダーの成果物は削除しません。

既存の監査ログの移行については [データ移行の仕組み](data-migrations.ja.md) を参照してください。設定の保存・取消・再起動後の復元は `desktop/LogRetentionUiSmoke.ps1` で隔離検証できます。

# リリース品質の改善計画

作業ブランチ: `codex/release-readiness`。既存のアイコン・ライセンス表示の変更を含むHEADから分岐。
公開・push・mainへのマージは行わない。日常利用のアプリ・設定とは分けた試験環境を使う。

1. 利用実績の永続集計: 直近500件の詳細履歴と日別・モデル別集計を分離する。
   実行状態の更新・再起動・移行で二重計上せず、トークン未報告とゼロ、キャッシュの分母、推定料金の意味を維持する。
2. 情報タブの診断・サポート: CLI確認、通知登録、更新・システム情報を表示する。
   通知試験にAI実行や承認を伴わせない。診断情報は許可リスト方式でプレビュー後にローカル保存する。
3. 更新の引き継ぎ: 「あとで」で終了した更新を、次回起動時に再検証して案内する。
   自動適用せず、適用時の実行・承認待ち・保存中のブロックを維持する。
4. 全般タブのデータと復旧: エージェント・接続先の非機密設定をバックアップする。
   復元は明示確認し、接続トークン・許可ユーザー・自動実行を引き継がない。作業フォルダーの信頼も別途確認する。
   アプリ内の履歴・会話メモ・利用実績・通知診断を選択して削除する。実行中や承認待ちには変更しない。
5. CIと説明: 初回起動・設定保持・基本画面のUIスモークを追加する。
   単体テストで更新復旧・統計・診断の秘密情報除外・設定復元の安全性を確認する。
   配布READMEの更新確認と「あとで」の説明を実装と一致させる。

機能単位で差分をレビュー・テストしてコミットし、最後にReleaseのポータブルビルドと
日英・ライト／ダークのUI検証を行う。Storeの製品登録・署名や証明書の信頼変更は対象外。

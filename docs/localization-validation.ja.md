# 英語・日本語対応の検証

対象は WinUI 3 デスクトップ版です。

## 言語の選択

- 初期値は「システムに合わせる」。Windowsユーザーの優先言語の先頭が `ja` または `ja-*` なら日本語、それ以外は英語にします。
- 初期設定の導入ページと全般の外観設定で、日本語・English・システムに合わせるを選べます。導入ページではすぐに表示を切り替え、通常画面では再起動の確認を表示します。
- `language.json` に独立して保存し、接続情報・許可ユーザー・承認モード・会話の関連付けは変更しません。設定が未作成・不明な値・不正なJSONの場合はシステム設定へ戻します。
- アプリが生成する画面文言、状態表示、確認ダイアログ、通知、利用規約・プライバシーポリシー、構成図を翻訳しました。CLI・外部サービスが返す文言やモデルの説明、利用者の入力はそのまま表示します。
- 日付・数値の地域設定は変更しません。チャットコマンド、プロバイダーID、承認判定用の状態値も維持しています。

WinUIの言語指定には [Windows App SDKのApplicationLanguages](https://learn.microsoft.com/en-us/windows/windows-app-sdk/api/winrt/microsoft.windows.globalization.applicationlanguages.primarylanguageoverride) を使い、最初のウィンドウ生成前に.NETとXAML両方の表示言語を設定します。

## 2026-10-24 の再点検

- 日英の承認投稿を「承認 / approval」に統一しました。通知とチャットの拒否ボタンも「拒否 / Reject」にそろえました。コマンドの `!cab approve` と `!cab reject`、承認コードは変更していません。
- Codex App Serverの進捗で `fileChange` などの内部識別子を表示していた箇所を翻訳しました。未対応の処理種別には、日英それぞれの一般的な処理名を使います。
- 全般・初期設定・構成図・読み上げ説明にDiscordの記載を追加し、日英で内容をそろえました。日英の構成図はそれぞれ20ラベルで、文字の重なりと描画範囲外がないことをエクスポート時に検査しています。
- 実画面で見つかったチャット設定の「両サービス共通」という古い説明を、日英とも各チャットサービスに共通する説明に直しました。
- CLI実行ファイルの選択ダイアログで、異なる翻訳リソースを参照していた箇所を修正しました。
- Windows通知の依頼・操作承認の見出しと本文、承認・拒否ボタン、期限切れ・再試行・失敗の表示が日英リソースを参照することを確認しました。OSによる通知バナーの配信確認は今回の対象に含めていません。
- 翻訳検査に `MrtText.Get` とXAMLの添付翻訳キーを追加しました。書式文字列の閉じ忘れやエスケープの不整合も検出します。
- 追加で指摘された更新マークの見切れは、標準InfoBadgeテンプレートが内側のアイコンを拡大することを確認し、24pxの円内の余白を広げて修正しました。情報画面の更新操作も右寄せにし、説明文の直後にボタンが浮く配置を解消しました。
- 全般の自動起動と自動接続は、同じ状態で同じアイコンになる実装を見直し、起動の電源アイコンと接続のリンクアイコンに分けました。状態の色、説明、読み上げ用の状態名は維持しています。

## 修正した問題

- 初期実装では.NETの文言だけが英語になり、XAMLが日本語のままになることを実画面テストで検出。Windows App SDK側への言語指定へ修正しました。
- 条件分岐で選ぶ3つの翻訳キーの不足を検出して追加し、検査スクリプトも条件付きのキー参照を検査するようにしました。
- 英語の「切断」「推論の強さ」「会話の切り離し」等の不明瞭な表現を修正しました。
- 作業フォルダーをチャットから変更できないと説明する古い文言を、現在の承認付き変更機能に合わせて日英とも修正しました。

# Slackの履歴表示名・再起動・キャッシュの実機検証

検証日：2026-10-19（日本時間）。リリース公開・アップロードは行っていない。

## 対象と認可設定の修正

実際の`ruhenheim`ワークスペース、既存のChat Agent Bridgeアプリとボットトークンを使用した。確認対象は`@ruhenheim1223 (ruhenheim)`、`#chat-agent-bridge`、ワークスペース名`ruhenheim`。

最初の実API確認ではユーザー名とワークスペース名を取得できたが、チャンネル情報は`missing_scope`だった。利用者の承認を受けて`channels:read`を追加し再認可した後、接続先がプライベートチャンネルであり、APIが`groups:read`を要求することを確認した。この追加も利用者が承認したため、同じアプリへ追加して再認可した。既存の暗号化済みトークンで`conversations.info`が成功し、`is_private: true`を確認した。

`C`から始まるIDでもプライベートチャンネルの場合がある。接頭辞で公開範囲を判断せず、実際のAPIの要求権限を確認する。ユーザー・チャンネル名の読み取りには、会話本文用の権限とは別のスコープが必要となる。[Slack公式の権限説明](https://docs.slack.dev/apis/web-api/using-the-conversations-api/)をセットアップ手順にも追加した。

アプリ本体の名前取得・キャッシュ処理には、この実機テストで修正を要する不具合は見つからなかった。コミット対象は検証用コード・スクリプトと手順・結果の記録である。

## 検証の構成

1. 取得処理のプローブは製品の`ChatIdentityDirectory`をそのまま使用する。内部テスト用コンストラクターへ記録用HTTPハンドラーを渡し、実際の`https://slack.com/api/`へ中継する。許可するメソッドは`auth.test`のPOST、`users.info`と`conversations.info`のGETだけで、リダイレクトは追わない。認証ヘッダー・応答本文は記録しない。
2. プローブのキャッシュとは別に、空のキャッシュを持つ独立したポータブルアプリを起動し、実APIから取得した名前の表示と検索を確認する。通常の一覧にはユーザー・チャンネル・ワークスペースの内部IDが出ないことを確認する。
3. アプリ側の設定を複製したデータフォルダーからトークンだけを外して再起動し、キャッシュのみで名前を表示できることを確認する。Slackサーバー自体を停止したテストではない。

既存アプリの停止、実行設定や許可リストの変更、AIの起動、チャット投稿、スレッド作成は行わない。元の`settings.json`・`sessions.json`・`history.json`・`audit.json`・`chat-identities.json`のハッシュ／ファイル有無が検証前後で同じことを確認する。

## 結果：すべて成功

| 対象 | 結果 |
|---|---|
| 初回の実API取得 | 認証確認・ユーザー名・チャンネル名の計3回。実際のSlack APIの200応答から3種類の名前を表示 |
| 有効なキャッシュを持つ取得処理の再生成 | 有効なトークンを渡したまま、API呼び出し0回。取得日時も不変 |
| ユーザー名だけを期限切れ | `auth.test`と`users.info`の計2回。チャンネルの再取得なし。チャンネル・ワークスペースを保存したレコードの取得日時は不変 |
| WinUIの表示と検索 | ユーザー名・チャンネル名・ワークスペース名を表示し、名前で検索可能。内部IDの通常一覧への露出なし |
| アプリを再起動してキャッシュのみで表示 | 複製した設定からトークンを外しても名前を表示。更新操作後も取得日時を維持 |
| 保存内容と既存データ | 名前キャッシュにトークン・メール専用項目・本文なし。アプリ設定のトークンはDPAPI保護。元の設定・履歴等のハッシュは一致 |

UIの3項目と取得処理の通信・期限切れ検証が成功した。最終の結果、プローブの呼び出し回数・取得日時、画面記録は`desktop/artifacts/slack-history-names-real-8e9c4efd58ac4449b7630e4929f3096f/`にローカル保存した。プローブのビルドは警告・エラー0件。テスト用アプリは終了済み。

## 再実行

```powershell
pwsh -NoProfile -File desktop/SlackHistoryNamesUiE2E.ps1 `
  -AppDirectory desktop/artifacts/mattermost-history-real-publish
```

この実行先は名前表示機能を含む既存のポータブルビルドである。`StatePath`で既存の実機テスト用メタデータのJSONを指定できる。ファイルには`NormalDataDirectory`、`ExpectedUserId`、`ChannelId`、`TeamId`、`WorkspaceUrl`を設定する。トークンはその設定保存先にあるDPAPI保護値を使用し、チャットやコマンド引数へ渡さない。実環境のAPIを呼ぶため、通常の単体テストからは自動実行しない。

プローブは既存のテストアセンブリ名を使用し、HTTPハンドラーを注入できる内部コンストラクターだけへアクセスする。製品の接続先や認証処理にテスト用の変更を入れていない。

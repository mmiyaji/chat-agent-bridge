# 利用実績の推定コスト

利用実績のコストは、保存済みのトークン数をAPIの標準単価へ換算した参考値です。サブスクリプションの支払い額、残高、請求額を表すものではありません。通貨はUSDです。グラフの表示や再計算ではAIを実行せず、保存済みの料金設定を使います。

## 料金表と計算

組み込みの [料金表](ChatAgentBridge.Core/Pricing/model-prices.json) は2026年10月20日に確認した値です。各単価は100万トークンあたりのUSDで、通常入力・キャッシュ読み取り・キャッシュ書き込み・出力を分けています。更新した料金表と手動指定はアプリのデータフォルダーに保存し、アプリを再起動しても維持します。

## 自動更新と手動指定

「履歴と会話 → 利用状況 → 利用量と推定コスト」の料金設定から、自動更新のオン・オフ、今すぐ更新、手動の単価指定を行えます。

| ファイル | 内容 | 更新する操作 |
| --- | --- | --- |
| `pricing-auto.json` | 取得済みの料金表、自動更新設定、確認日時など | 自動確認・今すぐ更新・自動更新設定の変更 |
| `pricing-manual.json` | モデルごとの手動指定 | 手動料金の保存・解除 |

いずれも接続設定と同じデータフォルダーに置きます。ポータブル版では通常、アプリの `Data` フォルダーです。画面に実際の保存先を表示します。自動更新は手動ファイルを書き換えません。

優先順位は **手動指定 → 自動取得した料金 → アプリ同梱の料金** です。モデル名が一致する手動指定を優先し、対応する日付付きのモデルIDにも適用します。具体的なモデルがわからない別名を推測する処理は追加しません。

手動指定はモデル単位で、通常入力・キャッシュ読み取り・キャッシュ書き込み・出力の4種類すべての料金を保存します。各料金は最小・最大の範囲で設定でき、固定単価なら両方に同じ数値を指定します。手動指定を解除すると、そのモデルの自動料金（なければ同梱料金）へ戻ります。手動指定だけで追加したモデルを解除すると、未算出に戻る場合があります。

手動ファイルの形式は次のとおりです。数値とモデル名は説明用の例で、実際の料金ではありません。通常はアプリ画面から編集できます。

```json
{
  "schemaVersion": 1,
  "models": [
    {
      "model": "example-model",
      "input": { "min": 1, "max": 1 },
      "cachedInput": { "min": 0.1, "max": 0.1 },
      "cacheWrite": { "min": 1.25, "max": 2 },
      "output": { "min": 5, "max": 5 }
    }
  ]
}
```

ファイルを直接編集した場合は「今すぐ更新」またはアプリの再起動で再読み込みします。手動ファイルの再読み込みは、料金表の通信に失敗した場合も反映します。

自動確認は有効な場合、起動後とその後の定期確認で、前回の確認から24時間以上経っていれば行います。「今すぐ更新」は自動更新がオフでも実行できます。同じ料金表ならETagによる変更確認で再ダウンロードを省きます。失敗時は最後の有効な料金表を保持し、状態を画面に表示します。新しい課金方式や未対応の料金表形式では、アプリ本体の更新が必要になる場合があります。

取得先は、このアプリのGitHub Pages上の[公開料金JSON](https://mmiyaji.github.io/chat-agent-bridge/pricing/models.json)に固定しています。GitHub Actionsが `main` 上の料金表を検証して配信するため、料金だけの変更でアプリを再ビルドする必要はありません。Pagesが404の場合のみ従来の [`main` 上の料金表](https://raw.githubusercontent.com/mmiyaji/chat-agent-bridge/main/desktop/ChatAgentBridge.Core/Pricing/model-prices.json)へフォールバックし、ETagは配信元ごとに区別します。取得するのは公開料金JSONだけで、履歴・プロンプト・接続トークンは送信しません。両方の取得に失敗した場合も保存済み・同梱料金を使います。配信手順は[CI/CDの運用手順](../docs/ci-cd.ja.md)を参照してください。

取得データは形式・通貨・トークン単位・モデルの重複・単価の範囲・サイズなどを検証し、不正なデータで有効な料金表を置き換えません。ローカルの手動ファイルが壊れている場合も自動修復で上書きせず、エラーと保存先を表示します。

**履歴の推定額は、その時点で有効な料金設定から再計算します。** 過去の推定額を固定したり、実行日当時の料金を自動選択したりする機能ではありません。料金の更新や手動指定で、過去の履歴の表示額も変わります。実行履歴自体は変更しません。

## トークンからの計算

基本式は次のとおりです。

```
(通常入力 × 入力単価
 + キャッシュ読み取り × 読み取り単価
 + キャッシュ書き込み × 書き込み単価
 + 出力 × 出力単価) / 1,000,000
```

入力トークン数にキャッシュ分が含まれる場合は、判明しているキャッシュ分を通常入力から差し引き、重複計上を防ぎます。キャッシュ内訳が不明でも入力全体が判明していれば、内訳によって変わる算定幅を表示します。キャッシュ分を別に報告する形式で必須の内訳が欠けている場合は、未算出にします。

キャッシュ保持期間や長いコンテキストへの料金条件を履歴だけでは特定できない場合も、確認できた標準単価の範囲で幅を表示します。グラフの棒の高さにはその上側の値を使います。範囲は、あらゆる請求条件を含む保証額ではありません。Fastモード、リージョン加算、ツールの追加料金、税、割引、為替換算は対象外です。

## 未算出と集計範囲

- 不明なモデル、未対応の単価、必要なトークン数の不足、不正な値は、0ドルとして扱いません。
- 実際に報告されたモデルを使います。設定で指定したモデルを、不明な実行モデルの代用にはしません。
- 算出できた実行と未算出の実行が混在する場合、表示額は算出できた分の小計です。算出件数を併記します。
- 選択した利用集計の範囲に合う実行だけを対象にし、会話の累積値と1実行分を足し合わせません。同じ実行IDも重複計上しません。
- 保存されたトークン数だけが対象です。CLIがサブエージェント等の利用量を含めていなければ、その分はこの推定にも含まれません。
- 表示の探索によって保存済みの実行履歴や接続設定を書き換えることはありません。

Claudeの `total_cost_usd` は、再開したセッションでは以前のコストを含む場合があります。この実装では、その値を各実行のコストとして加算せず、既存のトークン記録から計算します。

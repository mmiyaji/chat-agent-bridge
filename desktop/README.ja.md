# WinUI 3 ネイティブ版（開発プレビュー）

> 開発者向けの技術資料です。利用者向けの案内は [README](../README.ja.md)、現行の設定・運用ガイドは[ドキュメント索引](../docs/README.md)を参照してください。

`main` で開発する .NET 10 / WinUI 3 版です。画面は XAML、実行・接続は C# で構成し、旧ブラウザー UI や Node.js bridge は起動しません。外部エージェントはユーザーが別途導入・ログインする必要があります。

ウィンドウの最小サイズは幅500×高さ600 DIPです（表示倍率100%で500×600ピクセル）。Windowsの表示倍率に応じて下限も調整し、それより小さく縮める操作を防ぎます。内容が収まらない場合はページ内をスクロールできます。最大化・最小化は引き続き利用できます。

## 情報

ウィザードの必須入力ラベルにはテーマ対応色の「*」を表示し、読み上げ用にも必須属性を設定します。Discordの許可サーバーIDは、DMを許可しないときだけ必須表示になります。

初回ウィザードは、説明・注意事項、規約とプライバシーポリシーのリンク、同意チェック、構成図の順に表示します。構成図のプレビューは高さ160 DIPまでとし、クリックすると拡大ビューアーを開きます。小さなウィンドウではスクロールして全体を確認できます。

左メニュー下部の「情報」から、製品名・バージョン、更新、公式サイト・不具合報告と機能の提案、利用規約とプライバシーポリシーを確認できます。パッケージ識別名などはアプリの詳細から確認できます。「アプリを終了」ボタンはウィンドウの×と共通の確認ダイアログを開き、「終了する」「トレイに格納」「キャンセル」を選べます。トレイ常駐がオンでも、このボタンからは確認ダイアログを表示します。

トレイ常駐がオフの状態でウィンドウの×を押すと、「終了する」「トレイに格納」「キャンセル」を選べます。「トレイに格納」は今回だけの操作で、常駐設定は変更しません。「終了する」はチャット接続と実行中・承認待ちの処理を停止します。実行中・待機中の依頼がある場合は、確認画面を開いた時点の合計件数を表示し、展開するとAI処理中・ユーザーの回答待ち・承認待ち・追加指示の順番待ちの件数を確認できます。依頼内容や会話の識別情報は表示しません。既定の選択はキャンセルです。 終了処理中は「終了しています…」とローディングを表示して操作を停止し、切断と保存を最大5秒待ちます。トレイ格納時には表示しません。

「全般」の「システム トレイ」で、×で閉じてもバックグラウンドで稼働する設定を有効にできます（既定はオフ）。「タスクトレイに格納」は設定にかかわらず画面だけを隠します。常駐中もチャット接続、実行、承認待ち通知を維持します。トレイアイコンのクリックで画面を戻し、右クリックのメニューからも開く・完全終了を選べます。アイコンはWindowsの「隠れているインジケーター」に入る場合があります。設定画面の「完全終了」または「情報」の終了も、常駐設定にかかわらず切断・実行中断して終了します。PCのスリープ中・サインアウト後・終了後は動作しません。設定はデータフォルダー内の `background.json` に保存します。

Storeページと更新確認はMicrosoft Storeから配布されたパッケージで利用できます。開発プレビューでは未対応の理由を表示し、Storeへの問い合わせは行いません。更新確認はボタンを押したときだけ行い、更新操作はMicrosoft Storeで行います。

## ポータブル版

GitHub Actionsによるビルド・テスト・Releaseと更新JSONの配信については、[CI/CDの運用手順](../docs/ci-cd.ja.md)を参照してください。通常のPRは検証のみで、アプリの公開にはリリースタグが必要です。

Windows x64 / ARM64 向けの展開型プレビュー版は、ZIP 内の `ChatAgentBridge.Portable` フォルダー全体を書き込み可能な場所へ展開し、`ChatAgentBridge.Desktop.exe` を起動します。Windows 11 を推奨し、Windows 10 はバージョン 1809（ビルド 17763）以降に対応します。アプリ本体は .NET と Windows App SDK を含むため、別途ランタイムをインストールする必要はありません。インストーラー、MSIX登録、証明書、Windows 開発者モードは不要です。初回起動時に実行ファイルと同じ場所へ `Data` フォルダーを作成します。ZIP には利用者のデータや設定を含めません。利用するCLIは別途インストールし、CLI 自身でログインしてください。

アプリに保存した Slack / Mattermost 接続トークンは Windows DPAPI で保護され、同じ Windows ユーザーと PC で利用できます。他の PC へ設定をコピーする場合は元の PC でトークンを空にして保存し、移行先で再入力します。暗号化したまま移して読み込めなくなった場合は、終了後に `Data/settings.json` を退避して初期設定をやり直してください。CLIのログインと作業フォルダーも移行先で確認します。アプリフォルダーを移動する前に自動起動をオフにし、移動後に必要なら有効にしてください。削除するときは自動起動をオフにし、アプリを終了してからフォルダーを削除します。ユーザー単位の Windows 通知登録が残る場合があります。アプリは PC 全体へのインストールを行いません。

配布ZIPの作成・検査は `desktop/Create-PortableArchive.ps1` で行います。x64とARM64は別のZIPです。詳しい手順は[ポータブル版のリリース手順](../RELEASE.md)を参照してください。

ポータブル版は起動時と稼働中に定期的に更新を確認します。「情報 → 更新の設定」を開き、「定期的に更新を確認する」でオン／オフを切り替えられます。オフでも「ポータブル版の更新」の「更新を確認」は使えます。設定は変更時に保存されます。更新が見つかるとサイドバーの「情報」に丸付きのダウンロード矢印を表示し、ツールチップで更新先バージョンを確認できます。「リリースノート（GitHub）」から候補バージョンのGitHub Releaseページを開けます。候補がなければリリース一覧を開きます。

- **ダウンロード**。進捗・残り時間を表示します。一時停止やキャンセルができ、アプリを再起動しても続きから取得できます。
- **適用**。取得が完了したら「更新して再起動」を選びます。更新前に `Data` のバックアップを取ってください。
- **保守**。「情報 → 更新の設定」で使用容量を確認し、「情報 → 詳細設定 → 保守」から整理できます。
- **旧版からの移行**。更新プログラムを含まない旧版は、新しいZIPを手動で展開してください。

公開前の更新操作は、[アップデータのローカル試験](../docs/portable-update-tryout.ja.md)で再現できます。開発専用ビルドを旧版扱いで起動し、専用の設定とローカルZIPで更新します。通常のビルドには、この試験用の更新先指定は含めません。

ビルド・検証時の一時ファイルは、`Create-PortableArchive.ps1` と `PortableUpdateSmokeTest.ps1` の `-WorkingDirectory` で空きのあるドライブへ配置できます。既定は `desktop/artifacts` です。更新試験ではZIPの展開・インストール先・復元用バックアップを複製します。`-ExistingLayout` で実行済みの配置を再梱包するときは、空の `.cab-instance.lock` を配布対象から除外します。その他の `.cab-` 状態ファイルやデータフォルダーは配布対象として拒否します。

## Mattermostの直接接続

社内サーバーへプロキシを経由せず接続する場合は、「接続設定 → Mattermost」の「プロキシを使わず直接接続」をオンにして保存し、Mattermostを切断・再接続します。初回ウィザードでも設定できます。初期値はオフ（システムのプロキシ設定を使用）です。ユーザー名検索・投稿リンク確認・認証・WebSocketの受信・返信と接続通知に同じ設定を適用し、SlackやCLIの通信設定は変更しません。検索中の切り替えはその検索を取り消します。詳細は[接続ガイド](../docs/mattermost-setup.md#プロキシを使わず直接接続する)を参照してください。

## 手動実行の作業先と信頼範囲

手動実行の作業先はCABの展開先ではなく、エージェント設定の作業フォルダーです。PCで選択・保存すると信頼一覧にも追加します（許可範囲の拡大は保存前に確認）。信頼一覧が空の既存設定でも、現在の既定作業フォルダーを信頼する扱いは維持します。親フォルダーを登録すると下位フォルダーへも `!cab folder 絶対パス` で切り替えられます。チャットからの範囲外の指定は拒否し、自動登録しません。切り替えは会話の承認設定に従い、そのユーザー・スレッドにのみ適用します。ファイルそのものを移動する機能ではありません。Git管理は不要で、Codex execのGit確認はCABの信頼確認後に省略し、CLIの操作権限・サンドボックスは維持します。

## 全般

「全般」で起動・接続・表示の設定を変更できます。

| 設定 | 動作 |
| --- | --- |
| 自動起動・トレイ・言語・テーマ | 変更時に保存します |
| 自動接続 | 「自動接続先を保存」で、次回起動時の接続先を指定します |
| スリープ抑止 | 選んだ条件の間、Windowsの自動スリープを抑えます。初期設定はAC電源接続時に限ります。手動のスリープやふたを閉じる操作は引き続き有効です |

## 外観

「全般 → 言語と外観」の「カラーテーマ」で「ライト」「ダーク」「システムに合わせる」を選べます。初期値はシステムに合わせるです。選択すると画面・タイトルバーへすぐに反映し、再起動は不要です。確認ダイアログにも選択したテーマを使います。システムに合わせる場合はWindowsのアプリの配色設定に追従します。

外観の選択は `appearance.json` に独立して保存し、言語・接続・承認・モデル設定は変更しません。設定が未作成・不正・未知の値の場合はシステムに合わせます。Windowsのコントラストテーマの標準動作を維持するため、画面には標準コントロールとテーマ対応のブラシを使います。

実画面の検証は `desktop/AppearanceUiE2E.ps1 -Layout <パッケージ配置先> -DataDir <専用フォルダー>` で実行できます。専用フォルダーは `desktop/artifacts` 配下の新規フォルダーとし、`.cab-appearance-test` マーカーが必要です。CLIやチャットへは接続しません。

## 表示言語

初期値はWindowsの優先表示言語に合わせます。日本語（`ja` / `ja-*`）の場合は日本語、それ以外は英語を表示します。初期設定の導入ページ、または「全般 → 言語と外観」の「Language / 表示言語」で「システムに合わせる (System default)」「日本語 (Japanese)」「English」を選べます。初期設定の導入ページでは、説明・構成図・利用条件・ウィザードの文言へその場で反映します。同意のチェックや入力内容は維持します。通常の「全般」から変更すると、日英併記の再起動ダイアログが開きます。「今すぐ再起動」「後で」を選べます。実行・承認待ち・未保存の設定がある間は再起動できません。初回の導入ページでは再起動を求めず、その場で反映します。

画面、確認ダイアログ、Windows通知、利用規約・プライバシーポリシー、構成図を切り替えます。CLIやチャットサービス自身が返すエラー・モデル名・説明、利用者の入力は翻訳しません。日付・数値の地域設定はWindowsの設定を引き継ぎます。言語設定は設定保存先の `language.json` に独立して保存し、接続先や承認設定を変更しません。

翻訳のキー・書式引数は `python desktop/CheckLocalization.py` で検査できます。実画面の切替確認には `desktop/LanguageUiE2E.ps1` を使用します。このテストは `desktop/artifacts` 以下の `.cab-language-test` マーカーを持つ新規専用フォルダーが必要です。通常利用の設定では実行しないでください。

## 実行中の出力

「チャット設定 → 共通設定 → 実行中に届いたメッセージ」で、後から届いた依頼をどう扱うか選びます。

| 選択肢 | 対象と動作 |
| --- | --- |
| 順番に実行 | 現在の依頼が終わるまで待機します |
| 実行中の依頼へ追加 | Codex App Server・Claude Codeで、同じユーザーが同じスレッドに送った指示を追加します。毎回承認や未対応のCLIでは順番待ちになります |

追加の反映が確認できない場合は、画面と進捗投稿で知らせます。再送する前に、実行結果を確認してください。

Claude Codeの入力方式は[公式CLIリファレンス](https://code.claude.com/docs/en/cli-reference)、反映タイミングは[追加メッセージの処理](https://code.claude.com/docs/en/interactive-mode#when-claude-code-sends-what-you-queued)を参照してください。利用量は各応答の `usage`（メインエージェントの当該ターン分）を合算します。累積値の `modelUsage` や `total_cost_usd` は合算しません（[公式の集計範囲](https://code.claude.com/docs/en/agent-sdk/cost-tracking#track-costs-in-streaming-input-mode)）。

「手動で実行」と「チャット」の会話詳細には、実行中に開く「実行中の出力」欄があります。標準出力（`stdout`）、標準エラー（`stderr`）、コマンドやツールの進行状況（`activity`）を、最終結果と分けて確認できます。Codex App Serverの通知やCodex／Claude Code／Gemini／CopilotのJSON形式の出力は、対応する本文・操作状況を取り出して表示します。生の制御用JSONや認証イベント、内部の推論イベントは表示しません。CLIが出力をまとめて返す場合は、出力が届くまで待機表示になります。

表示更新は最大毎秒5回、保持する途中出力は末尾64,000文字です。上限を超えると古い部分を省略したことを表示します。「追従」を止めるか、出力を選択・上へスクロールすると表示を一時停止し、読み返しやコピーができます。この間もCLIは動き続け、最新の出力は上限内で受け取ります。追従を再開すると最新の表示へ戻ります。「表示を消去」は途中出力欄だけを消し、CLIの実行や最終結果には影響しません。

実行中は出力欄の「この依頼を中断」で、現在表示している依頼を停止できます。中断を要求すると停止処理が終わるまでボタンを無効にします。停止しても、エージェントがすでに行ったファイル変更は元に戻りません。チャットで別の会話を見ている間に依頼が実行中なら、画面上部の実行中依頼バナーからその依頼へ戻って停止できます。選択中の会話に対する停止操作は、その会話の依頼だけに適用されます。

Mattermostでは、Botが受付・実行中の進捗投稿に🛑（`octagonal_sign`）を付けます。依頼した本人がその🛑を押すと、その投稿に対応する依頼だけを中断できます。スタンプを探す必要はなく、承認待ちの依頼も取り消せます。同じスレッドの別の依頼、別ユーザーのリアクション、元の依頼文や結果本文へのリアクションは対象外です。完了時にはBot自身の🛑だけを取り外します。他のユーザーが付けたリアクションは削除しません。通信エラーなどで🛑が残っても、完了・失敗・中断・切断後の投稿は中断の対象になりません。Botトークンだけで利用でき、外部から接続可能なコールバックURLは不要です。🛑が表示されない場合や文字で操作する場合は、同じスレッドに `!cab stop` を返信します（こちらは本人の実行中・待機中の依頼が対象）。

中断の動作検証は `desktop/MattermostReactionCancellationSmoke.ps1 -AppDirectory <隔離ポータブルビルドの絶対パス> -TestAgentPath <TestAgent.exeの絶対パス>` で実行できます。ループバックの模擬Mattermostと専用CLIを使い、本人限定・依頼単位の中断、プロセス終了、待機中の別依頼の継続、完了後の無効化を確認します。外部のチャットやAIモデルには接続しません。

中止や失敗後も、その実行で受け取った途中出力はアプリを開いている間に確認できます。手動実行の次回開始時は表示をリセットし、チャットは依頼ごとに分離します。途中出力はPC内のメモリーだけで扱い、履歴ファイルへの保存、チャットへの自動投稿、引き継ぎ要約への追加、ファイル添付は行いません。既存の最終結果の共有設定とCLI自身の保存・通信動作は従来どおりです。

Claude Codeでは、途中メッセージを受け取る実行に `--include-partial-messages` を付けます。このオプションに対応するCLIが必要です。追加のAI呼び出しは行いません。UIの確認には、隔離したポータブルビルドとself-containedのTestAgentを使う `desktop/LiveOutputUiE2E.ps1` を使用します。実際のAIやチャットへの依頼は送りません。

## エージェントが作成したファイルの添付

「チャット設定」の承認・結果共有設定にある「生成ファイルの添付」で、本文の返信とは別に設定します。既存設定からの更新時も初期値は「毎回確認」です。実行完了後、チャットの会話詳細で「ファイルを添付」を押し、送信先・ファイル名・サイズを確認して、送るファイルを選択してから送信します。最初はどのファイルも選択されていません。本文の自動返信やCLIの実行承認だけで、ファイルが送られることはありません。

| 承認方法 | 動作 |
| --- | --- |
| 毎回確認（既定） | 毎回PCで選択・同意して送信 |
| スレッド初回だけ確認 | 初回に選択・同意すると、同じユーザー・会話・CLIセッション・実行条件で、以後の候補を制限内で自動添付 |
| 自動添付 | この設定を保存した場合に、候補を制限内で自動添付 |
| 添付禁止 | ファイルを送信しない |

初期上限は1ファイル10 MiB・1回3個・合計20 MiBです。それぞれ1～100 MiB・1～10個・合計1～100 MiBの範囲で変更できます。サービス側の上限が小さい場合は、そちらに従います。自動送信で制限を超える場合や検出が不完全な場合は、一部だけを勝手に送らずPCでの選択待ちになります。「結果を返信しない」設定では添付も無効です。送信失敗時は自動再送しません。一部だけ届いている可能性があるため、再送前にチャットを確認してください。

対象は、正常終了した実行の間に作業フォルダー内へ新規作成されたファイルです。既存ファイルの更新、作業フォルダー外、リンク、隠しファイル、設定・認証情報・鍵らしい名前のファイル、ツールの履歴・セッションなどのデータファイル（`.json`・`.jsonl`・`.log` など）、実行ファイルは対象外です。`author.md` や `session-notes.md` のような文書は対象です。名前で除外した新規ファイルは、件数とファイル名をPCの添付欄に表示します。検出には件数・読み込み量の上限があります。送信前にファイルの変更と内容のハッシュを再確認しますが、ファイル本文に含まれる機密情報を判定する機能ではありません。選択時に内容も確認してください。添付候補の選択は受信画面を開いている間だけ保持します。

チャットからは「資料を新しいファイルとして作成し、添付用に用意してください」のように依頼できます。添付候補を検出できる接続では、CLIにもアプリ側が添付を担当することを伝えます。CLI自身がSlackやMattermostへアップロードする必要はありません。既定の「毎回確認」では、実行完了後にPCの「チャット」で添付候補を選び、送信に同意してください。依頼文やCLIの返答だけでは添付への同意にはなりません。

添付の承認と上限が適用されるのは、このアプリが送信する添付です。上限は1回の送信単位で、スレッド全体の累計ではありません。CLIに与えたOS・ネットワーク権限を隔離する機能ではないため、フルアクセスのCLIによる独自の通信や、同じWindowsユーザー権限での設定ファイル変更までは防ぎません。また、ファイル内容を本文として返信するかどうかは、本文の結果共有設定に従います。

初回同意はユーザー・接続先・会話・CLIセッションと実行／添付条件に結び付きます。セッション再開に対応しないCLIでは、承認は1回の送信に限られます。作業フォルダー、エージェント、モデル、許可ユーザー、添付上限などを変えた場合は同意を取り直します。設定や認証情報を添付データに含めません。SlackにはBotの `files:write` 権限が必要です。権限が不足した場合は画面に案内を表示し、アプリの権限を自動変更しません。Mattermostは既存のBotトークンで、指定スレッドへファイル付き投稿を作成します。送信後の閲覧範囲はチャットのチャンネル・スレッドの公開範囲に従います。

その他のCLIなど、会話の継続用セッションIDを追跡できない連携では、「初回のみ確認」でも実行ごとに確認します。継続を確認できない実行へ以前の同意を流用しません。

画面テストは `desktop/FileAttachmentsUiE2E.ps1 -AppDirectory <隔離ポータブルビルド> -TestAgentPath <self-contained TestAgent.exe> -Portable -Language ja`（英語は `en`）で実行します。ローカルの模擬Mattermostと専用ファイルだけを使い、実際のSlack／MattermostやAIへは依頼・添付を送りません。TestAgentは開発専用で、配布物に含めません。アプリの設定保存先とテスト用作業フォルダーは兄弟ディレクトリに分けます。設定保存先内のファイルは添付の対象外です。

## 会話一覧の幅調整

「履歴と利用状況」の会話一覧と詳細の境界を左右にドラッグして幅を変更できます。境界にキーボードのフォーカスを合わせ、左右キーでも調整できます。調整した幅はアプリを開いている間、会話の選択変更やタブ移動後も維持します。狭い画面では一覧と詳細を切り替える表示になり、画面を広げると調整した幅へ戻ります。

## 利用状況と振り返り

「履歴と利用状況」の「利用状況」では、日別の利用カレンダー、利用量のグラフ、曜日ごとの利用傾向を表示します。30日・90日・1年で期間を切り替えられ、利用回数・利用日数・期間内の最長連続利用・最も使った日も確認できます。カレンダーの日付を選ぶと、その日の実行回数・トークン数・推定コストを表示します。「この日の実行記録を見る」で、その日に絞った実行記録の表へ移動し、絞り込みのボタンで解除できます。

集計はこのアプリに保存された最新500件までの実行が対象です。実行を開始したPCの日付で数え、失敗や中止も含めます。日付の区切りにはPCのタイムゾーンを使います。CLIを直接利用した分、保存前・破棄済みの記録、プロバイダー側の利用状況は含みません。追加のAI呼び出しや通信・履歴本文の保存は行いません。モデルの使用回数はCLIが報告したモデル名を優先し、未報告なら指定されたモデル名で集計します。両方未記録の場合も区別して表示します。

`desktop/ActivityUiE2E.ps1 -AppProcessId <PID> -DataDir <隔離保存先> -Language ja` で、期間の連続切り替えと件数、日付からの履歴表示、ライト／ダーク、500・1160 DIPでの表示、設定・履歴を書き換えないことを検査できます。保存先は `desktop/artifacts` 配下とし、`.cab-activity-test` マーカーと、今日の実行を含む模擬履歴を用意します。英語表示のアプリには `-Language en` を指定します。

## 利用できるCLI

初期設定とエージェント設定では、Codex、Claude Code、Gemini CLI、GitHub Copilot CLI、Antigravity CLI、Muse Code Preview、その他のCLIを選べます。各CLIを事前にインストールし、必要なログインをCLI自身で完了してください。

| CLI | 会話の自動継続 | モデル・推論候補 | CLIチェック |
| --- | --- | --- | --- |
| Codex / Claude Code | 対応 | CLIから取得 | バージョンとモデル候補 |
| Gemini CLI / GitHub Copilot CLI | 対応（ユーザー・スレッドごとの会話IDで再開） | アプリでモデル名を指定。推論はCLI側の設定 | バージョン・CLIの識別 |
| Antigravity CLI（`agy`） | 対応（ユーザー・スレッドごとの会話IDを `--conversation` で再開） | `agy models` から取得、またはモデル名を指定。推論はCLI側の設定 | バージョン（`agy --version`）・CLIの識別 |
| Kiro CLI（`kiro-cli`、Windows 11） | ユーザー・スレッドごとのIDを `--resume-id` で再開（実サービス未検証） | CLIからモデル候補を取得、または直接指定。推論・権限はCLI側の設定 | バージョン・CLIの識別 |
| Qwen Code（`qwen`） | ユーザー・スレッドごとのIDを `--resume` で再開（実サービス未検証） | モデルIDを直接入力。推論・権限はCLI側の設定 | バージョン・CLIの識別 |
| Kimi Code CLI（`kimi`） | ACPセッションIDを保存して継続（実サービス未検証） | モデル名または設定済み別名を直接入力。「継承」はツール操作の承認を要求、「フルアクセス」はKimiが受け付けた場合のみ | バージョン・CLIの識別 |
| Muse Code（`muse`） | Preview。`muse exec --session-id` でCABの会話を継続（実サービス未検証） | モデル名を直接指定。モデル一覧と推論設定の選択には未対応。権限はMuse Code側で管理 | バージョン・CLIの識別 |
| その他のCLI | 未対応（毎回独立した実行） | CLI設定・起動引数で指定 | バージョンのみ |

Gemini CLIは `--output-format stream-json`、GitHub Copilot CLIは `--output-format json` に対応する版が必要です。会話IDと完了イベントを確認できない出力は失敗として扱い、別のユーザーや直前のCLI会話に接続しません。モデル名はエージェント設定・初期設定・会話のモデル変更画面、または対象スレッドの `!cab model <モデル名>` から指定します。空欄または `!cab model default` はCLI／アプリの既定値に戻します。この版ではGemini・Copilotの候補取得は未対応です。CLI自身で利用可能なモデル名を確認してください。Antigravity CLIは、エージェント設定の「CLIモデル候補を取得」（CLIチェック後にも自動で試行）で `agy models` の一覧から選べます。

対応するCLIを確認・登録すると、PCの会話詳細や `!cab agent <codex|claude|gemini|github-copilot|antigravity|muse> <summary|fresh>` で切り替えられます（`agy` は `antigravity` の別名です）。`summary` は会話メモを参考情報として引き継ぎ、`fresh` はメモを渡しません。新しいCLIの会話は別の会話IDで開始し、実行権限や依頼承認を会話メモから変更しません。

Antigravity CLI（`agy`）は実行中に確認画面を出せません。編集やコマンド実行を許可する場合は、次のいずれかを選びます。

- **CLIの既定値を使う**。agyの `settings.json` にある許可ルールを使います。
- **フォルダー内の編集を自動許可**。作業フォルダー内の編集を許可します。
- **フルアクセス**。CLIの権限制限を解除するため、信頼できる作業に限って使ってください。

拒否された操作があれば返信の末尾に表示します。読み取り専用、操作ごとの確認、推論の強さの指定には対応していません。

その他のCLIは、非対話モードで標準入力から依頼を受け取り、標準出力へ結果を返す必要があります。操作権限はCLI側の設定に従い、アプリから権限の解除やサンドボックスの追加は行いません。チャットの依頼承認・結果返信・許可ユーザーの制限は共通して適用します。CLIチェックの成功は、認証、モデルの利用可否、AIの実行成功を示しません。チェックでAIへの依頼は送りません。

CLI実行ファイルは、エージェント設定の「詳細：CLIの場所と起動引数」と、初期設定ウィザードのAI選択ページにある「参照…」から選べます。選択・キャンセルだけでは設定を保存せず、CLIも実行しません。選択後はCLIチェックで確認してから保存してください。通常は `.exe`、Codex・Gemini・GitHub Copilotは公式npmランチャーの `.cmd`、Codexは `.ps1` も選択できます。

CLIの導入やPATHの変更後は「環境変数を再読み込み」で、現在のWindowsユーザー・システムの環境変数をアプリへ反映できます。Windows側の設定は書き換えません。CLI実行・チェック・候補取得・設定保存中は使用できません。確認済みのCLIとモデル候補はリセットされるため、CLIチェックをやり直してください。反映先は次に起動するCLIです。

Windowsの公式npmパッケージは、インストール済みのパッケージ名と実行エントリーを確認してNode.jsから直接起動します。コマンドスクリプトをシェルで実行しません。独自のインストール形態で検出できない場合は、実行ファイルと非対話用引数を手動指定してください。

ファイル選択と環境変数更新の画面テストは `desktop/CliToolsUiE2E.ps1 -AppProcessId <PID> -DataDir <隔離保存先> -Executable <Claude実行ファイル>` で確認できます。日本語表示・Claude Code設定の隔離アプリを使い、保存先を `desktop/artifacts` 配下に作り、`.cab-cli-tools-test` マーカーを置いてください。選択とキャンセル、勝手に設定を保存しないこと、CLIチェックのリセット、ウィザード、最小幅500 DIPでのライト／ダーク表示を検査します。CLIチェックは行いますが、AIへの依頼は実行しません。画面記録と結果は隔離保存先の `cli-tools-review` に保存します。

サイドバー下部は、接続先サービスのアウトラインアイコンと「サービス名・状態」を表示します。状態マークは接続中・接続処理中・エラー・未接続で変わり、折りたたみ時も表示されます。クリックするとチャット画面へ移動します。

## 使い方

1. 「エージェント設定」でCLI・モデル・作業フォルダーを指定して保存します。作業フォルダーは絶対パスの入力、またはフォルダー選択ボタンで指定できます。保存後にチャットを再接続すると、新しい会話に設定が適用されます。Codex CLI、Claude Code CLI、その他のCLIを選べます。モデル名が空欄ならCLIの既定値を使います。Codex の既定引数は `exec --json -` です。任意の CLI を設定する場合は標準入力からプロンプトを受け取れる形式を指定してください。Codexの対話的な承認・追加入力を使う場合は「Codex App Serverを使う」をオンにします。このモードの引数は固定です。
2. 接続設定でサービスの認証情報を入力して保存します。チャンネルID欄の「チャンネルを検索」からBotが参照できるチャンネルを名前で検索できます。Mattermostでは選んだチャンネルを送信先に設定し、Slack・Discordでは既存の許可チャンネルIDに追加します。Discordの候補は設定済みの許可サーバーID内に限られます。Slackで権限不足が表示された場合は、Bot Token Scopesに `channels:read` と `groups:read` を追加してアプリを再インストールしてください。手入力も引き続き利用できます。許可ユーザーは「共通設定 → 許可ユーザー」で管理し、Mattermost・Slack はユーザー名検索またはID入力、Discord はID入力で追加します。HTTPS、またはローカルホストの HTTP が利用できます。各サービスの設定画面からも、そのサービスの許可ユーザー数を確認して共通一覧へ移動できます。
3. チャットからどちらかのプロバイダーへ接続します。設定変更後は切断・再接続してください。保存済みチャットへの自動接続を有効にした場合は、アプリ起動後に接続します。
4. Mattermostでは指定チャンネル・DMに `!cab 依頼内容` または先頭に接続したBotへのメンション（例：`@cc-agent-bot 依頼内容`）を付けて投稿します。未公開の `0.1.0-preview.5` ビルドでは、開始した本人が元のスレッドへ普通に返信して続けられます。未開始のスレッドや別ユーザーの普通の返信は取り込みません。保存済みのAIセッションまたは承認済み作業先があれば再接続後も継続でき、未保存のまま切断した場合は再度メンションか `!cab` で開始します。メンション対応は `v0.1.0-preview.4` 以降で、それ以前は `!cab` を使います。Slackでは最初にBotをメンションし、CLIの会話IDが保存された後は同じ本人が同じスレッドへ普通に返信すると会話を継続できます。Slackの通常返信には対象チャンネルの `message.channels` / `message.groups` イベントの購読も必要です。初期設定では返信ごとにPCまたはWindows通知で実行を承認します。
5. PC に表示された依頼を選択し、「内容を確認して実行」で作業フォルダーと実行内容を承認します。この手順は「会話ごとに最初の依頼を確認」「毎回確認」の場合です。初期値の「許可ユーザーは確認なし」では、許可ユーザーの依頼はPCでの確認なしに実行します。

初期設定の自動返信は完了／失敗の状態だけです。結果の自動共有は実行ポリシーで明示的に有効にします。結果本文は「結果をスレッドに送信」で元の送信先と本文を確認してから共有できます。長い本文は先頭4,000文字まで送ります。Codexでは最終エージェントメッセージを抽出し、ツール出力だけのイベント列は本文として送りません。

実行の起点は保存した作業フォルダーで、信頼フォルダーの許可範囲も確認します。チャットから実行ファイル・引数は変更できません。作業フォルダーは下記の承認付きコマンドで、その会話について信頼範囲内に限り変更できます。信頼フォルダーの判定は CLI 自体のファイルアクセスを OS で制限する機構ではありません。

許可済みのユーザーが許可範囲内のチャンネル・スレッドで、`!cab folder C:\Projects\app` を投稿すると、その会話の作業フォルダーを変更できます。パスに空白がある場合は引用符で囲みます（例: `!cab folder "C:\Projects\my app"`）。このコマンドはPCのWindows通知で必ず承認し、自動承認設定でも省略しません。コマンド自体ではCLIやモデルを呼び出しません。指定先は現在の信頼フォルダー内である必要があります。信頼フォルダーが空の場合は初期作業フォルダーだけを暗黙の信頼範囲とし、兄弟フォルダーを使うにはPCから明示的に信頼する親フォルダーを設定してください。チャットから信頼範囲は広げられません。

フォルダー変更はプロバイダー・サーバー・ユーザー・チャンネル・スレッドが一致する会話だけに適用し、再起動後も維持します。その会話の保存済みCLIセッション関連付け、会話別モデル・推論強度・ポリシー上書き、初回承認を解除します。実行履歴と他ユーザー・他スレッドの状態は維持され、次のメッセージから新しいCLIセッションを全体承認設定で始めます。同じ会話で待機中の依頼があれば無効化し、再投稿を求めます。エージェント設定で全体の作業フォルダーを変更した場合は新しい会話に適用します。旧フォルダーに保存済みセッションがある会話は、必要に応じて `!cab folder` でその会話を切り替えてください。

### 許可ユーザーの一覧

「チャット設定 → 共通設定 → 許可ユーザー」では、サービス列付きの表で、全サービスの許可ユーザーと合計件数を表示します。初期表示は各サービスから順に1件ずつ、全体で6件まで並べます。「残り○件を表示」で展開できます。「ユーザーを追加」でサービスを選び、Mattermost・Slack のユーザーを検索して追加するか、ID を直接入力できます。Discord は ID を入力します。変更は設定を保存すると反映されます。各サービスのタブから一覧を開くことも、「IDをまとめて編集」を開くこともできます。 名前または ID をクリックすると、登録日時・最後の依頼日時と、保存済み履歴の実行・会話・CLI セッション件数を確認できます。削除時は対象を確認します。

### Mattermostの許可ユーザーと会話を指定する

許可ユーザーには表示名や `@ユーザー名` ではなく、Mattermost内部のユーザーIDを保存します。接続設定または初期設定ガイドでサーバーURLとトークンを入力し、ユーザー名を検索すると、該当アカウントを確認して「許可ユーザーに追加」できます。検索だけでは許可されません。追加後は接続設定を保存し、切断・再接続してください。

会話を限定する場合は、接続設定の「チャットのアカウント・会話範囲」で、Mattermost投稿のメニューからコピーしたリンクを貼り付け、「会話を確認」→「この会話を追加」→保存・再接続の順に操作します。返信のリンクでも最初の投稿IDを取得します。対象は設定したサーバーとチャンネル内の、削除されていない既存の会話です。スレッドリストが空欄なら追加制限なし、登録がある場合は登録済みの会話だけで依頼でき、新規の会話は開始できません。ユーザーの許可も引き続き必要です。

### Slackの許可ユーザーと会話を指定する

接続設定または初期設定ガイドでSlackユーザー名（`@`付きでも可）かメンバーIDを検索すると、認証したSlackワークスペース内のアカウントを確認できます。結果を確認して「このユーザーを追加」を選んだときだけ、許可ユーザーの下書きにメンバーIDを追加します。検索だけでは許可されません。ユーザー検索に `users:read` が必要な場合は、Slackアプリにスコープを追加して再インストールし、必要なら新しいボットトークンを接続設定へ入力してください。追加後は設定を保存し、Slackを再接続してください。

会話を限定するには、接続設定の「チャットのアカウント・会話範囲」でSlackメッセージのリンクを確認します。リンク先のワークスペース、実際のチャンネル、会話のルートタイムスタンプを表示するので確認後に「この会話を追加」を選んでください。必要なチャンネルIDとルートスレッドIDを一緒に下書きへ追加し、保存・再接続すると反映されます。空のチャンネル一覧とスレッド一覧は追加の会話制限を設けません。チャンネル一覧に登録した場合はそのチャンネル内、スレッド一覧に登録した場合は指定した会話内に依頼を限定します。ボットが対象チャンネルを読める必要があり、必要なSlack APIスコープが不足しているときは画面に表示します。

Docker上の実サーバーを使う検証は、[テスト・検証ガイド](../docs/testing.ja.md)を参照してください。専用アカウント、隔離データ、TestAgentで実行します。

### Codex・Claude Codeセッションの継続

実行ファイルがCodexで、引数が標準の `exec --json -` の場合、プロバイダー・接続先・チャンネル・スレッド・ユーザーごとにセッションIDを保存します。同じユーザーの同じスレッドの次の依頼はそのIDで `exec resume --json <id> -` を使い、アプリ再起動後も継続できます。[公式の非対話モード仕様](https://learn.chatgpt.com/docs/non-interactive-mode)

Claude Codeの標準プロファイルも、CLIが返す明示的なセッションIDを保存し、同じチャットスレッドの次の依頼を `--resume <id>` で再開します。出力は `--output-format stream-json --verbose`、通常の依頼文は標準入力で渡します。「実行中の依頼へ追加」では `--input-format stream-json --replay-user-messages` を利用し、同一セッションに追加指示を渡します。曖昧な直前会話の継続は使いません。Claude Codeからの操作承認や質問への回答は、この方式では未対応です。

ワークスペースや実行ファイル・引数を変更した場合は、保存済みセッションをそのまま別設定で使いません。「履歴とセッション」で切り離してから新規依頼を実行してください。切り離しは関連付けだけを削除し、Codex自身のセッションや実行履歴は削除しません。実行中の同じスレッドの処理があれば、終了まで待って解除します。

任意のCLI・カスタム引数・手動実行画面からの実行は、現在は単発実行です。新規実行を途中でキャンセルし、CLIのセッションIDを取得できなかった場合、その新規セッションはbridgeに紐付きません。Codex自身のセッション保存はCLIの設定に従います。

### App Serverの承認と追加入力

アクセス申請を処理する際は、申請時の接続先と保存済みの接続先、現在の会話制限を照合します。Codex App Serverの「継承」では、Bridgeが適用する作業フォルダー内の書き込み・必要時の確認・ネットワークなしを表示します。

App Serverモードでは `thread/start` / `thread/resume` / `turn/start` を使い、チャットスレッドへの関連付けを保存します。execとの切替には関連付けの解除が必要です。手動実行画面は単発実行です。[公式App Server仕様](https://learn.chatgpt.com/docs/app-server)

コマンド実行・ファイル変更の許可は初期設定ではPCのダイアログで回答します。操作承認の公開を有効にした場合は、元の依頼者による同じスレッドへの `!cab approve <コード>` / `!cab reject <コード>` で回答できます。最初の回答だけが有効で、5分経過・切断・キャンセルは拒否します。最初の依頼の実行確認は引き続きPCで必要です。追加入力はPC上の選択肢・テキスト欄で回答し、チャットには転送しません。

明確に破壊的な一部のコマンドでは、PCの承認ダイアログ・Windows通知・チャットの操作承認に警告と該当理由を表示します。警告は参考情報で、通常の承認方法は変わりません。分類は網羅的ではなく、実際の操作権限と基本的なガードはCLI側の設定に従います。一般的なパッケージ導入、通常のGit操作、単独のファイル削除、通常のネットワーク通信では警告しません。

実行設定は承認ポリシー `on-request`、sandbox `workspaceWrite`、ネットワーク無効を要求します。追加権限の要求は付与せず、未対応の要求や別thread/turnへの要求は拒否します。外部CLI側が実際に適用する制限と対応バージョンは、実Codexでの検証が残っています。

### 履歴と監査

- **実行履歴**。時刻・結果・終了コード・作業先などを保存し、最新500件を表示します。
- **保存エラー**。結果を退避できた場合は、履歴アクセスや再起動時に修復し、「履歴保存エラーあり」と表示します。結果が分からない記録は「中断」とし、自動で再実行しません。
- **監査ログ**。受信・承認・共有などを記録します。アプリ内の例外では、原因分類・例外型・HRESULTを記録し、診断をCLI出力の前に表示します。

履歴・復旧ファイル・監査ログには、依頼や結果の本文、トークン、例外メッセージを保存しません。診断にもスタックや例外に含まれるパス・引数は入りません。

接続エラーでは認証情報を含む可能性のあるサーバー応答を表示しません。接続先・権限・ネットワークを確認して再接続してください。アプリを閉じると受信と実行を停止します。トレイ常駐・自動再接続・自動起動はまだありません。

### Mattermostのユーザー・公開範囲の制約

「チャット設定」に許可するユーザーIDを登録して保存してください。表示名ではなく正確なIDを指定します。空欄のままでも、許可ユーザー以外からの依頼（Botへのメンション・`!cab`・DiscordのDM）はチャット画面に表示され、「許可して実行」「今回だけ実行」「拒否」から選べます。「許可して実行」は許可ユーザーに追加して保存し、次回から確認なしで受け付けます。同じユーザーの承認待ちは1件にまとめ、拒否したユーザーからの依頼は10分間表示しません。許可・拒否と設定画面での追加・削除は、操作したWindowsユーザーとともに操作履歴へ記録します。許可の取り消しは保存後の待機中・実行中の依頼にも適用し、実行・操作許可・結果共有の直前にも設定を再確認します。ユーザーの追加後は再接続してください。

保存セッションは提供元・接続先・チャンネル・スレッド・投稿者で分離します。同じスレッドでも別ユーザーには別のAI会話を作ります。Mattermostの接続先はサーバーURLから識別します。旧形式の所有者不明セッションは自動継続せず、新しい会話を作ります。古い関連付けは履歴画面で確認・解除できます。この分離はCLIのファイルアクセスをOSで隔離するものではありません。

結果本文の送信はPCで確認します。送信先は依頼元のスレッドであり、閲覧者全員に公開されます。Codex App Serverの操作承認は初期状態でPCだけに表示します。「操作承認の詳細をスレッドに公開」を有効にした場合だけ、コマンド・説明・作業フォルダーと承認コードを投稿します。コードの利用は元の依頼者・チャンネル・スレッドに限定されますが、投稿内容の閲覧範囲はMattermost/Slackの権限に従います。ローカルの履歴・監査JSONには依頼本文や結果本文を保存しませんが、CLI側の会話履歴とは別の管理です。

Mattermostへの接続開始時の案内投稿は既定でオフです。「接続設定 → Mattermost」の「接続時に案内を投稿する」をオンにして保存すると、次の接続開始時に設定したチャンネルへ投稿します。設定項目がない旧版の保存データもオフとして扱います。通信障害からの自動再接続では案内を重複投稿しません。明示的な切断時には引き続き接続状態と再投稿の案内を通知します。切断中の依頼を履歴から取り込む処理はありません。通信障害中やアプリの強制終了時には通知を送れないため、PCの接続状態を確認して必要な依頼を再投稿してください。PCで拒否・キャンセルした依頼にも本文を含まない状態通知を返します。通知失敗はPCに表示します。PCでの操作が必要な追加質問や、手動共有を選んだ場合の結果共有はPCで行います。

### 開発プレビュー ZIP

再配布可能な自己完結型プレビュー ZIP は、署名用の秘密鍵を含む PFX と、対応する公開 CER を指定して作成します。既定の PFX パスワードは `password` です。異なるパスワードの PFX を使う場合は `-CertificatePassword (Read-Host -AsSecureString)` を指定してください。秘密鍵は ZIP に含まれません。

```powershell
.\desktop\Create-ReleaseArchive.ps1 `
  -Certificate 'C:\certificates\preview.pfx' `
  -PublicCertificate 'C:\certificates\preview.cer' `
  -ReleaseVersion '0.1.0-preview.1' `
  -PackageVersion '0.1.0.0'
```

`-Architecture x64` が既定値です。ARM64 ビルドが利用できる場合は `-Architecture ARM64` を指定できます。成果物は `desktop/artifacts/releases` に作成されます。生成した ZIP は次のコマンドで、ZIP 内容、SHA-256、パッケージ署名、証明書の一致、固定プレビュー identity を再検証できます。

```powershell
.\desktop\Create-ReleaseArchive.ps1 -ValidateOnly -Architecture x64 -PackageVersion '0.1.0.0' -ArchivePath 'desktop/artifacts/releases/ChatAgentBridge.WinUI.Preview-0.1.0-preview.1-x64.zip'
```

既に同じ identity・version・architecture で署名済みの MSIX がある場合は `-ExistingPackage` にそのファイルを指定し、アーカイブだけを作り直せます。たとえば、次のようにします。

```powershell
.\desktop\Create-ReleaseArchive.ps1 `
  -Certificate 'C:\certificates\preview.pfx' `
  -PublicCertificate 'C:\certificates\preview.cer' `
  -ExistingPackage 'desktop/artifacts/release-payload/x64/ChatAgentBridge.WinUI.Preview.msix' `
  -Architecture x64 -PackageVersion '0.1.0.0'
```

ZIP には MSIX、公開 CER、日英のインストール案内、検証・インストール用スクリプト、SHA-256 一覧だけが入ります。初回は CER を「ローカル コンピューター > 信頼されたユーザー」に管理者として登録する必要があります。インストールスクリプトは昇格せず、実行した Windows ユーザーにだけ MSIX を追加します。自己署名プレビュー証明書は Store で信頼される証明書ではありません。開発用 identity と分けた `ChatAgentBridge.WinUI.Preview` を使うため、開発版とは別アプリとしてインストールされます。

## 起動設定・モデル設定

「エージェント設定」のモデル名は、このアプリがCLIを起動する際に指定します。Codexは `--model` またはApp Serverのturnパラメーター、Claude Codeは `--print --output-format stream-json --verbose --model` を使用し、依頼文は標準入力で渡します。CLI自身の設定ファイルやログイン情報は変更しません。「その他のCLI」は手動の引数をそのまま使います。

会話の詳細のメニューから既定のエージェント設定を開けます。保存済みの会話を選び「次回の実行モデルを設定」を使うと、その会話にだけ適用するモデルを指定できます。空欄で保存すると既定モデルへ戻ります。実行中の会話では終了を待って変更し、実行中のモデルは切り替えません。

Windowsログイン時の自動起動と、アプリ起動後のチャット自動接続は別の設定です。自動起動の変更はWindowsのStartupTaskに即時反映し、OSで無効にした場合はタスクマネージャーの案内を表示します。自動接続先は設定保存後、次回起動から適用します。初期値はいずれも無効です。ウィンドウを閉じたときの動作はシステムトレイ設定で選びます。依頼の承認はチャット設定に従います。

接続中に既定のCLI・モデルを変更した場合は、切断して再接続してください。会話ごとのモデル上書きは次回の実行開始時に読み直します。

### CLIからモデル候補を選ぶ

「エージェント設定」の「CLIモデル候補を取得」を押すと、現在入力しているCLIと作業フォルダーで候補を取得します。候補を選ぶとモデル名の欄にIDが入り、「設定を保存」で確定します。取得だけでは入力中のモデル名や保存済み設定は変わりません。候補にないIDも手入力でき、空欄ならCLIの既定モデルを使います。

「履歴と利用状況」から会話ごとのモデル変更を開いた場合も取得できます。ここでは、その会話に保存されたCLI・作業フォルダーを使います。取得に失敗した場合や、その他のCLIを使う場合は手入力してください。

CodexはApp Serverの `model/list`、Claude Codeはstream-jsonの初期化応答から取得します。一覧取得では依頼文や推論要求を送らず、取得後は専用プロセスを終了します。自動取得・定期ポーリングは行いません。表示される一覧はCLIが提示した候補であり、契約上の利用可否や料金を保証するものではありません。[Codex公式仕様](https://learn.chatgpt.com/docs/app-server)、[Claude公式SDKの初期化処理](https://github.com/anthropics/claude-agent-sdk-python/blob/main/src/claude_agent_sdk/_internal/query.py)

### 推論の強さを選ぶ

CLIモデル候補を取得してモデルを選ぶと、そのモデルの「推論の強さ」を選べます。候補はCodexの `supportedReasoningEfforts` とClaude Codeの `supportedEffortLevels` から取得し、アプリ側の固定リストは使いません。CLIが候補を返さないモデルでは既定値のみを使います。強さを上げると応答時間やトークン消費が増えることがあります。

未指定の場合はCLIに設定を任せます。モデル名を変更すると以前の推論指定は解除されます。保存済みの値は候補取得前にも表示しますが、CLIが現在の候補として確認したものとは区別します。会話別のモデル変更画面でも選択でき、モデルと推論の強さをまとめて保存します。会話別の指定がない場合はエージェント設定を使いますが、会話に別モデルを指定した場合は、そのモデルのCLI設定に任せます。

Codexの通常実行では `model_reasoning_effort` 設定、App Serverでは `turn/start.effort`、Claude Codeでは `--effort` に渡します。CLI自身の設定ファイルは変更しません。[Codex App Server](https://learn.chatgpt.com/docs/app-server)、[Claude Code CLI](https://code.claude.com/docs/en/cli-reference)

## 利用量と起動効率

手動実行・チャットの結果と「履歴と利用状況」に、CLIが報告する入力・出力・キャッシュ読込／書込トークン、観測範囲、起動・初期化・待機・合計時間を表示します。未報告の値は「未取得」です。指定モデルと、利用量に実際に報告されたモデルは区別します。依頼本文と実行結果は実行履歴に保存しません。

`MeasureAppServerStartup.ps1 -Executable <codex.exeの絶対パス>` はinitializeだけを計測し、推論を開始しません。今回のローカル3回計測は起動＋初期化89～407msでした。実モデルの応答時間・料金削減率を測った値ではありません。

## 会話の一覧と操作

チャットでは、チャットサービス・接続先・チャンネル・スレッド・利用者が同じ依頼を一つの会話にまとめます。新しく受信した順に表示し、利用者・スレッド・依頼内容・作業フォルダーで検索、承認待ち・実行中・終了済みで絞り込めます。同じスレッドでも利用者が異なる会話は別々です。一覧を選ぶと詳細が開き、会話内の依頼を切り替えて承認・拒否・停止・結果共有を操作します。停止は、選択した依頼が実行中の場合だけ使えます。結果と利用量も依頼ごとに表示し、出力の保持は1件64,000文字を上限とします。

履歴と利用状況では、会話・実行記録・利用状況をタブで切り替えます。タブ名に件数を表示します。保存済み会話は検索・チャットサービスによる絞り込みに対応し、更新後も同じ会話の選択を維持します。会話を続けるには元のチャットスレッドへ返信してください。「次回は新しい会話」は確認後に紐付けを解除し、次の依頼を新しいセッションで開始します。本文や実行結果を履歴へ保存する変更はありません。狭いウィンドウでは一覧と詳細を切り替え、戻るボタンで一覧に戻れます。会話の詳細には、その会話の最近の実行を最大5件表示し、選ぶと実行記録の詳細を開きます。

「実行記録」タブでは、実行を開始・会話・ユーザー・結果・モデル・所要時間・トークンの7列の表で表示します。列見出しのクリックで並べ替え、右端のドラッグで幅を変更できます。行をクリックすると詳細が横に開き、ID が一致する操作の時系列、使用量の内訳、ID・作業フォルダーを表示します。「会話を開く」で会話タブの該当する会話へ移動します。幅の広いウィンドウでは表と並べて、狭い場合は表の上に重ねて表示し、閉じるボタンか Esc で閉じます。表示を「すべての操作」に切り替えると、実行に至らなかった拒否や実行 ID のない記録も含め、時刻・操作・サービス・会話の4列で確認できます。「アクセス許可」は、許可ユーザーの追加・削除とチャットからの許可・拒否だけを表示します。設定の許可ユーザー一覧の記録ボタンからも、そのユーザーに絞って開けます。チャット・ユーザー・ID の検索とサービスで絞り込め、「すべての操作」では操作の種類でも絞り込めます。チャット名をまだ取得できていない行は ID で表示し、表の上に一度だけ案内を出します。監査ログの出力はこのタブから行います。

### トークン・キャッシュ・推定コストの振り返り

「履歴と利用状況 → 利用状況 → 利用量と推定コスト」で、実行回数・トークン消費量・キャッシュヒット率・推定コストを切り替えられます。直近28日の日別グラフと、選択期間（30日・90日・1年）のモデル別グラフを表示します。日ごとの内訳は、利用カレンダーで日付を選ぶと表示します。

- 集計範囲は「実行ごと」と「最後のリクエストのみ」を分けています。後者は部分的な利用量であり、実行全体の合計ではありません。一般的なセッション累積値は二重計上を避けるため除外します。
- 入力はキャッシュの読み込み・書き込みを重複なく含め、入力と出力がともに報告された実行のトークン合計を表示します。キャッシュヒット率は、キャッシュ読み込みの合計を対応する入力トークンの合計で割ります。率の単純平均は使いません。
- CLIが報告していない値やモデル名は推測せず「未報告」と表示します。入力0のキャッシュ率も算出しません。グラフでは「0＝報告値0」「?＝未報告」「·＝実行なし」を区別し、報告件数と対象件数を併記します。請求額・利用枠・他のアプリでの利用量を表すものではありません。
- Claude の result.usage は実行単位の値です。以前のアプリで thread-total と誤分類された既存の Claude 履歴も、保存データを書き換えずに実行単位として扱います。累積の modelUsage は足し合わせません。CLIがモデル別の内訳を報告できない場合は「モデル未報告」にまとめます。[公式の集計範囲の説明](https://code.claude.com/docs/en/agent-sdk/cost-tracking)
- 日別利用カレンダーの期間外の日付は「–」付きの枠で示します。実行0の日とは区別でき、日付を選ぶと期間外であることも確認できます。

推定コストは保存済みトークン数と報告モデルに対応する公開標準API料金から算出し、料金を確認した日付と公式料金ページを「算定方法」に表示します。料金が不明なモデル・トークンは未算出のままにし、表示額が部分小計なら算定件数も併記します。キャッシュ情報が不足する場合は範囲で示し、グラフの高さには範囲の上限を使います。請求額ではなく、サブスクリプション料金、ツール、Fastモード、リージョン、税などを含まない参考値です。詳しい算定範囲と根拠は[推定コストの算定方法](COST_ESTIMATION.md)を参照してください。

料金設定では、自動取得した料金表と手動料金を別々のファイルに保存します。手動指定を優先し、解除すると自動料金へ戻ります。自動更新は1日1回の確認に抑え、「今すぐ更新」からも取得できます。通信失敗時も保存済みの料金表を利用します。料金設定を変更すると過去の履歴の推定額も再計算されます。詳しい保存先・優先順位・取得先は[推定コストの算定方法](COST_ESTIMATION.md)に記載しています。

利用量の集計は保存済み履歴（最大500件）だけを読み、追加のAIリクエストや履歴のクラウド同期を行いません。料金表の自動更新が有効な場合、公開料金JSONだけを取得します。

概要の「現在の状態」には、Windowsサインイン時の自動起動と、アプリ起動時の自動接続（オフ／Slack／Mattermost）も表示します。各カードを押すと「チャット設定」の起動設定へ移動し、該当する操作欄にフォーカスします。表示する自動接続先は保存済みの設定です。自動起動はWindowsの実際の状態を確認し、Windows側の無効化・ポリシー制限・利用不可も区別します。オフは任意の設定として中立色で表示します。

自動起動の切り替え中と完了直後はスイッチを一時的に無効にし、連打を受け付けません。全般画面での状態取得も同じ排他制御を使います。切り替えが拒否された場合でも、Windowsが返した状態へ表示を戻してから次の操作を受け付けます。

信頼する作業フォルダーは、「エージェント設定」の「フォルダーを選んで追加」または「現在の作業フォルダーを追加」で下書きへ追加し、「設定を保存」で適用します。手入力は1行に1フォルダーで、行を削除すれば一覧から外せます。親フォルダーを信頼すれば、その下の子・孫フォルダーも対象です。たとえば C:\Projects を登録すると C:\Projects\App1 も対象になり、C:\Projects-other は対象になりません。一覧が空なら、現在の作業フォルダーとその配下を信頼します。外部を指すリンク先は信頼範囲に含めません。この設定は実行を開始できる場所の制限で、CLIのファイルアクセス全体をOSで隔離する設定ではありません。

### Muse・Kimiの実行と承認

Museの依頼文は作業フォルダー外のユーザー専用一時ファイルに保存し、終了・失敗・キャンセル後に削除します。異常終了で残った入力は起動時と次回Muse実行時に整理し、実行中のleaseを持つファイルは削除しません。リンクを含む作業先は実体パスで一時入力領域と重ならないことを確認します。

Kimiの承認画面には取得できた実行コマンドを渡して危険度を判定します。内容を判定できないツール操作は注意を表示します。承認待ちの時間は実行時間制限から除外します。会話再開時にモード一覧が省略されても、設定したモードを明示的に要求し、CLIが受け付けない場合は依頼を実行しません。

Museのイベントで会話の存在と実行との紐付けを確認した後に失敗した場合は、確認済みIDを保存して同じスレッドの次の依頼で再開します。プロセスを起動しただけのIDや別セッションのIDは保存せず、失敗した依頼は成功・初回承認済みには変更しません。Muse・Kimiの中断はキャンセルトークンで処理し、実行中への追記は未対応のため順番待ちになります。

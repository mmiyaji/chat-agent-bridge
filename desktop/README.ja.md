# WinUI 3 ネイティブ版（開発プレビュー）

`codex/winui-rebuild` で開発する新しい .NET 10 / WinUI 3 版です。画面は XAML、実行・接続は C# で構成し、旧ブラウザー UI や Node.js bridge は起動しません。外部エージェントはユーザーが別途導入・ログインする必要があります。

## 情報

左メニュー下部の「情報」から、製品名、実際のパッケージのバージョンと識別名、提供者・問い合わせ先・ソースコード、Storeの配布状態、更新内容、利用規約とプライバシーポリシーを確認できます。終了ボタンでは、チャットの切断と実行中の作業の中止を確認してからアプリを閉じます。

Storeページと更新確認はMicrosoft Storeから配布されたパッケージで利用できます。開発プレビューでは未対応の理由を表示し、Storeへの問い合わせは行いません。更新確認はボタンを押したときだけ行い、更新操作はMicrosoft Storeで行います。

## 外観

左メニュー下部の「外観」の「カラーテーマ」で「ライト」「ダーク」「システムに合わせる」を選べます。初期値はシステムに合わせるです。選択すると画面・タイトルバーへすぐに反映し、再起動は不要です。確認ダイアログにも選択したテーマを使います。システムに合わせる場合はWindowsのアプリの配色設定に追従します。

外観の選択は `appearance.json` に独立して保存し、言語・接続・承認・モデル設定は変更しません。設定が未作成・不正・未知の値の場合はシステムに合わせます。Windowsのコントラストテーマの標準動作を維持するため、画面には標準コントロールとテーマ対応のブラシを使います。

実画面の検証は `desktop/AppearanceUiE2E.ps1 -Layout <パッケージ配置先> -DataDir <専用フォルダー>` で実行できます。専用フォルダーは `desktop/artifacts` 配下の新規フォルダーとし、`.cab-appearance-test` マーカーが必要です。CLIやチャットへは接続しません。

## 表示言語

初期値はWindowsの優先表示言語に合わせます。日本語（`ja` / `ja-*`）の場合は日本語、それ以外は英語を表示します。初期設定の導入ページ、または左メニュー下部の「外観」の「Language / 表示言語」で「システムに合わせる (System default)」「日本語 (Japanese)」「English」を選べます。初期設定の導入ページでは、説明・構成図・利用条件・ウィザードの文言へその場で反映します。同意のチェックや入力内容は維持します。通常の「外観」から変更すると、日英併記の再起動ダイアログが開きます。「今すぐ再起動」「後で」を選べます。実行・承認待ち・未保存の設定がある間は再起動できません。初回の導入ページでは再起動を求めず、その場で反映します。

画面、確認ダイアログ、Windows通知、利用規約・プライバシーポリシー、構成図を切り替えます。CLIやチャットサービス自身が返すエラー・モデル名・説明、利用者の入力は翻訳しません。日付・数値の地域設定はWindowsの設定を引き継ぎます。言語設定は設定保存先の `language.json` に独立して保存し、接続先や承認設定を変更しません。

翻訳のキー・書式引数は `python desktop/CheckLocalization.py` で検査できます。実画面の切替確認には `desktop/LanguageUiE2E.ps1` を使用します。このテストは `desktop/artifacts` 以下の `.cab-language-test` マーカーを持つ新規専用フォルダーが必要です。通常利用の設定では実行しないでください。

## 利用状況と振り返り

「履歴と会話」の「利用状況」では、日別の利用カレンダー、直近28日の日別ヒストグラム、曜日ごとの利用傾向、よく使うモデル上位5件を表示します。30日・90日・1年で期間を切り替えられ、利用回数・利用日数・期間内の最長連続利用・最も使った日も確認できます。カレンダーの日付を選び「この日の実行履歴を見る」で、その日の記録へ移動できます。実行タブの「日付の絞り込みを解除」で一覧へ戻ります。

集計はこのアプリに保存された最新500件までの実行が対象です。実行を開始したPCの日付で数え、失敗や中止も含めます。日付の区切りにはPCのタイムゾーンを使います。CLIを直接利用した分、保存前・破棄済みの記録、プロバイダー側の利用状況は含みません。追加のAI呼び出しや通信・履歴本文の保存は行いません。モデルの使用回数はCLIが報告したモデル名を優先し、未報告なら指定されたモデル名で集計します。両方未記録の場合も区別して表示します。

`desktop/ActivityUiE2E.ps1 -AppProcessId <PID> -DataDir <隔離保存先> -Language ja` で、期間の連続切り替えと件数、日付からの履歴表示、ライト／ダーク、500・1160 DIPでの表示、設定・履歴を書き換えないことを検査できます。保存先は `desktop/artifacts` 配下とし、`.cab-activity-test` マーカーと、今日の実行を含む模擬履歴を用意します。英語表示のアプリには `-Language en` を指定します。

## 利用できるCLI

初期設定とエージェント設定では、Codex、Claude Code、Gemini CLI、GitHub Copilot CLI、その他のCLIを選べます。各CLIを事前にインストールし、必要なログインをCLI自身で完了してください。

| CLI | 会話の自動継続 | モデル・推論候補 | CLIチェック |
| --- | --- | --- | --- |
| Codex / Claude Code | 対応 | CLIから取得 | バージョンとモデル候補 |
| Gemini CLI / GitHub Copilot CLI | 未対応（毎回独立した実行） | CLI設定・起動引数で指定 | バージョン・CLIの識別 |
| その他のCLI | 未対応（毎回独立した実行） | CLI設定・起動引数で指定 | バージョンのみ |

基本連携のCLIは、非対話モードで標準入力から依頼を受け取り、標準出力へ結果を返す必要があります。操作権限はCLI側の設定に従い、アプリから権限の解除やサンドボックスの追加は行いません。チャットの依頼承認・結果返信・許可ユーザーの制限は共通して適用します。CLIチェックの成功は、認証、モデルの利用可否、AIの実行成功を示しません。チェックでAIへの依頼は送りません。

CLI実行ファイルは、エージェント設定の「詳細：CLIの場所と起動引数」と、初期設定ウィザードのAI選択ページにある「参照…」から選べます。選択・キャンセルだけでは設定を保存せず、CLIも実行しません。選択後はCLIチェックで確認してから保存してください。通常は `.exe`、Codex・Gemini・GitHub Copilotは公式npmランチャーの `.cmd`、Codexは `.ps1` も選択できます。

CLIの導入やPATHの変更後は「環境変数を再読み込み」で、現在のWindowsユーザー・システムの環境変数をアプリへ反映できます。Windows側の設定は書き換えません。CLI実行・チェック・候補取得・設定保存中は使用できません。確認済みのCLIとモデル候補はリセットされるため、CLIチェックをやり直してください。反映先は次に起動するCLIです。

Windowsの公式npmパッケージは、インストール済みのパッケージ名と実行エントリーを確認してNode.jsから直接起動します。コマンドスクリプトをシェルで実行しません。独自のインストール形態で検出できない場合は、実行ファイルと非対話用引数を手動指定してください。

ファイル選択と環境変数更新の画面テストは `desktop/CliToolsUiE2E.ps1 -AppProcessId <PID> -DataDir <隔離保存先> -Executable <Claude実行ファイル>` で確認できます。日本語表示・Claude Code設定の隔離アプリを使い、保存先を `desktop/artifacts` 配下に作り、`.cab-cli-tools-test` マーカーを置いてください。選択とキャンセル、勝手に設定を保存しないこと、CLIチェックのリセット、ウィザード、最小幅500 DIPでのライト／ダーク表示を検査します。CLIチェックは行いますが、AIへの依頼は実行しません。画面記録と結果は隔離保存先の `cli-tools-review` に保存します。

## 構成

概要画面には、別の端末からSlack／Mattermostを窓口として、起動中のローカルPCのCodex／Claude Code CLIへ依頼する構成図と操作手順を表示します。依頼する端末でデスクトップアプリを使えない場合のチャット経由の操作窓口です。初期設定ではPCでの実行確認と結果共有の確認が必要です。実行ポリシーで承認・共有方法を変更できます。

概要画面は「エージェント設定」「チャット設定」「接続状態」「CLIの確認」の短い状態とアイコンを表示します。各タイルから設定やチャットへ移動でき、手順・構成図・保存先などの「セットアップの詳細と構成」は初期状態で開きます。必要に応じて折りたためます。詳細の展開状態は画面を移動しても維持し、読み込み成功や初期設定完了の常設バナーは表示しません。未保存の変更やエラーは確認できる表示を残します。

概要画面のセットアップ進捗は「AIと作業フォルダー」「チャット接続情報」「チャットへの接続成功」の3段階です。各ボタンから該当画面へ移動できます。未保存の編集は完了数に含めず、接続処理中も接続完了とは区別します。切断すると接続ステップは未完了に戻ります。この概要の進捗表示は、初回設定ウィザードの5ステップとは別です。

初回起動時は5ステップの専用ウィザードを表示します。1) 構成図と利用規約・プライバシーポリシー、2) AIと既存の作業フォルダー、3) CLIの種類・バージョンとモデル・推論候補、4) SlackまたはMattermostの接続情報と許可ユーザーID、5) 承認・結果共有・操作権限と接続確認、の順です。タイトルは「[1/5] はじめに・利用条件」の形式とし、戻るを左下、次へを右下に固定します。

導入ページの同意欄は新規開始時に未選択です。両方への同意後、文書バージョンとUTC日時だけをPC内の `consent.json` へ保存して進みます。個人IDや同意情報を外部へ送信しません。進行中の再起動では、同意済みなら必要に応じてステップ3のCLI再確認へ戻り、同意がない場合は導入ページへ戻ります。「後で設定」で保留でき、概要画面から再開できます。既存設定のある利用者へウィザードを強制しません。規約とプライバシーポリシーは概要からいつでも閲覧できます。

文面の確認用ファイルは [利用規約](../docs/terms.ja.md) と [プライバシーポリシー](../docs/privacy-policy.ja.md) です。現状有姿・無保証とし、法令上免除できない責任を除外しています（[消費者庁の逐条解説](https://www.caa.go.jp/policies/policy/consumer_system/consumer_contract_act/annotations)参照）。提供者は mmiyaji、問い合わせ先は mail@ruhenheim.org です。文書版は 2026-10-18.1 として同意記録と対応付けます。文面は開発プレビュー用です。アプリの表示元は `Onboarding/PolicyText.cs` です。

CLIチェックは `--version` による種類・バージョン・実行ファイルの確認と、プロバイダーが対応する場合のモデル候補初期化を行います。依頼文やユーザーターンを送らず、モデル実行・課金状態・利用権限・ログインや認証の成功を保証しません。候補と推論レベルはCLIの初期化応答に基づきます。AIまたは作業フォルダーを変更した場合はCLIチェックをやり直し、チャット設定を変更した場合は再接続が必要です。ウィザードの完了には、設定を保存したうえで接続成功が確認されている必要があります。初期値は「毎回承認」「手動共有」です。アプリ起動時のチャット接続は最終ステップで選べます。Windowsログイン時のアプリ起動は、完了後に接続設定の「起動と自動接続」で変更します。

図の編集元は `docs/assets/overview/OverviewArchitecture.svg`、アプリが読み込む画像は `Assets/OverviewArchitecture.png` です。更新時はリポジトリの開発依存関係とMicrosoft EdgeがあるWindows環境で `node desktop/ExportOverviewDiagram.mjs` を実行します。ブラウザーは画像書出し時のみ使用し、アプリ実行時には不要です。

- `ChatAgentBridge.Desktop`: WinUI 3、MVVM、概要・手動実行画面・接続設定・チャット受信・履歴とセッション。
- `ChatAgentBridge.Core`: 設定、Windows DPAPI、CLI実行・停止・排他、Codexセッション継続、履歴と監査の永続化。
- `ChatAgentBridge.Transports`: Slack Socket Mode / Mattermost WebSocket。受信と返信を担当し、エージェントを直接実行しません。
- `*.Tests`: CLI・保存・イベントフィルター・承認の自動テスト。実通信テストは明示的に有効化した場合だけ実行します。
- `ChatAgentBridge.TestAgent`: モデルを呼ばずにApp Serverの承認・追加入力を再現する開発専用プロセス。配布パッケージには含めません。

## ビルド・起動

Windows、.NET 10 SDK、Windows App SDK 用 WinUI テンプレート、WinApp CLI、開発者モードが必要です。

```powershell
cd desktop/ChatAgentBridge.Desktop
.\BuildAndRun.ps1 -SkipRun
.\BuildAndRun.ps1 -Detach
```

ビルドスクリプトは既定で .NET CLI を使用します。Visual Studio の MSBuild を使う場合は `.NET 10` 対応版を用意し `-UseVisualStudioMSBuild` を指定してください。

```powershell
dotnet test desktop/ChatAgentBridge.Core.Tests/ChatAgentBridge.Core.Tests.csproj
dotnet test desktop/ChatAgentBridge.Transports.Tests/ChatAgentBridge.Transports.Tests.csproj
```

## 使い方

1. 「エージェント設定」でCLI・モデル・作業フォルダーを指定して保存します。作業フォルダーは絶対パスの入力、またはフォルダー選択ボタンで指定できます。保存後にチャットを再接続すると、新しい会話に設定が適用されます。Codex CLI、Claude Code CLI、その他のCLIを選べます。モデル名が空欄ならCLIの既定値を使います。Codex の既定引数は `exec --json -` です。任意の CLI を設定する場合は標準入力からプロンプトを受け取れる形式を指定してください。Codexの対話的な承認・追加入力を使う場合は「Codex App Serverを使う」をオンにします。このモードの引数は固定です。
2. 接続設定で認証情報と許可ユーザーIDを入力して保存します。Mattermost には対象チャンネル ID も指定します。HTTPS、またはローカルホストの HTTP が利用できます。
3. チャット受信からどちらかのプロバイダーへ接続します。設定変更後は切断・再接続してください。保存済みチャットへの自動接続を有効にした場合は、アプリ起動後に接続します。
4. Mattermost では指定チャンネルに `!cab 依頼内容` を投稿します。Slack では最初に bot をメンションします。CLIの会話IDが保存された後は、同じ本人が同じスレッドへ普通に返信すると会話を継続します。未開始のスレッドや別ユーザーの会話への返信は自動で取り込まず、メンションまたはスレッド内の `!cab 依頼内容` で明示的に依頼します。通常のスレッド返信には、対象チャンネルの `message.channels` / `message.groups` イベントの購読も必要です。初期設定では返信ごとにPCまたはWindows通知で実行を承認します。
5. PC に表示された依頼を選択し、「内容を確認して実行」で作業フォルダーと実行内容を承認します。チャット受信の承認方法は、会話の実行ポリシーに従います。初期設定は毎回承認です。

初期設定の自動返信は完了／失敗の状態だけです。結果の自動共有は実行ポリシーで明示的に有効にします。結果本文は「結果をスレッドに送信」で元の送信先と本文を確認してから共有できます。長い本文は先頭4,000文字まで送ります。Codexでは最終エージェントメッセージを抽出し、ツール出力だけのイベント列は本文として送りません。

実行の起点は保存した作業フォルダーで、信頼フォルダーの許可範囲も確認します。チャットから実行ファイル・引数は変更できません。作業フォルダーは下記の承認付きコマンドで、その会話について信頼範囲内に限り変更できます。信頼フォルダーの判定は CLI 自体のファイルアクセスを OS で制限する機構ではありません。

許可済みのユーザーが許可範囲内のチャンネル・スレッドで、`!cab folder C:\Projects\app` を投稿すると、その会話の作業フォルダーを変更できます。パスに空白がある場合は引用符で囲みます（例: `!cab folder "C:\Projects\my app"`）。このコマンドはPCのWindows通知で必ず承認し、自動承認設定でも省略しません。コマンド自体ではCLIやモデルを呼び出しません。指定先は現在の信頼フォルダー内である必要があります。信頼フォルダーが空の場合は初期作業フォルダーだけを暗黙の信頼範囲とし、兄弟フォルダーを使うにはPCから明示的に信頼する親フォルダーを設定してください。チャットから信頼範囲は広げられません。

フォルダー変更はプロバイダー・サーバー・ユーザー・チャンネル・スレッドが一致する会話だけに適用し、再起動後も維持します。その会話の保存済みCLIセッション関連付け、会話別モデル・推論強度・ポリシー上書き、初回承認を解除します。実行履歴と他ユーザー・他スレッドの状態は維持され、次のメッセージから新しいCLIセッションを全体承認設定で始めます。同じ会話で待機中の依頼があれば無効化し、再投稿を求めます。エージェント設定で全体の作業フォルダーを変更した場合は新しい会話に適用します。旧フォルダーに保存済みセッションがある会話は、必要に応じて `!cab folder` でその会話を切り替えてください。

### Mattermostの許可ユーザーと会話を指定する

許可ユーザーには表示名や `@ユーザー名` ではなく、Mattermost内部のユーザーIDを保存します。接続設定または初期設定ガイドでサーバーURLとトークンを入力し、ユーザー名を検索すると、該当アカウントを確認して「許可ユーザーに追加」できます。検索だけでは許可されません。追加後は接続設定を保存し、切断・再接続してください。

会話を限定する場合は、接続設定の「チャットのアカウント・会話範囲」で、Mattermost投稿のメニューからコピーしたリンクを貼り付け、「会話を確認」→「この会話を追加」→保存・再接続の順に操作します。返信のリンクでも最初の投稿IDを取得します。対象は設定したサーバーとチャンネル内の、削除されていない既存の会話です。スレッドリストが空欄なら追加制限なし、登録がある場合は登録済みの会話だけで依頼でき、新規の会話は開始できません。ユーザーの許可も引き続き必要です。

### Slackの許可ユーザーと会話を指定する

接続設定または初期設定ガイドでSlackユーザー名（`@`付きでも可）かメンバーIDを検索すると、認証したSlackワークスペース内のアカウントを確認できます。結果を確認して「このユーザーを追加」を選んだときだけ、許可ユーザーの下書きにメンバーIDを追加します。検索だけでは許可されません。ユーザー検索に `users:read` が必要な場合は、Slackアプリにスコープを追加して再インストールし、必要なら新しいボットトークンを接続設定へ入力してください。追加後は設定を保存し、Slackを再接続してください。

会話を限定するには、接続設定の「チャットのアカウント・会話範囲」でSlackメッセージのリンクを確認します。リンク先のワークスペース、実際のチャンネル、会話のルートタイムスタンプを表示するので確認後に「この会話を追加」を選んでください。必要なチャンネルIDとルートスレッドIDを一緒に下書きへ追加し、保存・再接続すると反映されます。空のチャンネル一覧とスレッド一覧は追加の会話制限を設けません。チャンネル一覧に登録した場合はそのチャンネル内、スレッド一覧に登録した場合は指定した会話内に依頼を限定します。ボットが対象チャンネルを読める必要があり、必要なSlack APIスコープが不足しているときは画面に表示します。

Dockerの実サーバーでの追加検証には `MattermostRealUserLookupUiE2E.ps1 -AppProcessId <PID> -DataDir <隔離保存先>` と `MattermostThreadLinkUiE2E.ps1 -AppProcessId <PID> -DataDir <隔離保存先> -Language ja` を使います。前者は日本語表示・許可ユーザーが空の状態で開始します。専用Reviewパッケージ、`desktop/artifacts` 内の `.cab-activity-test` マーカー付き保存先、`StartMattermostE2E.ps1` / `PrepareMattermostWorkflowE2E.ps1` で作る localhost:8070 の実サーバーとテストアカウントが必要です。CLIは `artifacts/mattermost-ui-agent/claude.exe` に配置したTestAgentと同一のオフラインホスト、承認は「初回のみ」、結果は「自動共有」、自動接続は無効にした設定を使用します。AIモデルは呼び出さず、実投稿・PCでの承認・返信・セッション継続・未許可ユーザー／会話の拒否を確認します。結果と画面記録は隔離保存先へ保存します。通常利用の設定には実行しないでください。

### Codex・Claude Codeセッションの継続

実行ファイルがCodexで、引数が標準の `exec --json -` の場合、プロバイダー・接続先・チャンネル・スレッド・ユーザーごとにセッションIDを保存します。同じユーザーの同じスレッドの次の依頼はそのIDで `exec resume --json <id> -` を使い、アプリ再起動後も継続できます。[公式の非対話モード仕様](https://learn.chatgpt.com/docs/non-interactive-mode)

Claude Codeの標準プロファイルも、CLIが返す明示的なセッションIDを保存し、同じチャットスレッドの次の依頼を `--resume <id>` で再開します。出力は `--output-format stream-json --verbose`、依頼文は通常の標準入力です。曖昧な直前会話の継続は使いません。実行中の追加質問には対応しません。

ワークスペースや実行ファイル・引数を変更した場合は、保存済みセッションをそのまま別設定で使いません。「履歴とセッション」で切り離してから新規依頼を実行してください。切り離しは関連付けだけを削除し、Codex自身のセッションや実行履歴は削除しません。実行中の同じスレッドの処理があれば、終了まで待って解除します。

任意のCLI・カスタム引数・手動実行画面からの実行は、現在は単発実行です。新規実行を途中でキャンセルし、CLIのセッションIDを取得できなかった場合、その新規セッションはbridgeに紐付きません。Codex自身のセッション保存はCLIの設定に従います。

### App Serverの承認と追加入力

App Serverモードでは `thread/start` / `thread/resume` / `turn/start` を使い、チャットスレッドへの関連付けを保存します。execとの切替には関連付けの解除が必要です。手動実行画面は単発実行です。[公式App Server仕様](https://learn.chatgpt.com/docs/app-server)

コマンド実行・ファイル変更の許可は初期設定ではPCのダイアログで回答します。操作承認の公開を有効にした場合は、元の依頼者による同じスレッドへの `!cab approve <コード>` / `!cab reject <コード>` で回答できます。最初の回答だけが有効で、5分経過・切断・キャンセルは拒否します。最初の依頼の実行確認は引き続きPCで必要です。追加入力はPC上の選択肢・テキスト欄で回答し、チャットには転送しません。

実行設定は承認ポリシー `on-request`、sandbox `workspaceWrite`、ネットワーク無効を要求します。追加権限の要求は付与せず、未対応の要求や別thread/turnへの要求は拒否します。外部CLI側が実際に適用する制限と対応バージョンは、実Codexでの検証が残っています。

### 履歴と監査

`history.json` に実行時刻・状態・終了コード・スレッド・ワークスペース・セッションID、`audit.json` に受信・承認・拒否・実行・共有・解除のメタデータをそれぞれ最大500件保存します。プロンプト・結果本文・トークン・例外本文はこれらのファイルへ保存しません。異常終了後に残った実行中記録は「中断」と表示します。終了状態の保存に失敗した場合も実行結果とは分けて警告します。

接続エラーでは認証情報を含む可能性のあるサーバー応答を表示しません。接続先・権限・ネットワークを確認して再接続してください。アプリを閉じると受信と実行を停止します。トレイ常駐・自動再接続・自動起動はまだありません。

### Mattermostのユーザー・公開範囲の制約

「接続設定」に許可するユーザーIDを登録して保存してください。Mattermost・Slackとも空欄は全員拒否で、既存設定にもIDの追加が必要です。表示名ではなく正確なIDを指定します。受信した依頼はPCで確認するまで実行しません。許可の取り消しは保存後の待機中・実行中の依頼にも適用し、実行・操作許可・結果共有の直前にも設定を再確認します。ユーザーの追加後は再接続してください。

保存セッションは提供元・接続先・チャンネル・スレッド・投稿者で分離します。同じスレッドでも別ユーザーには別のAI会話を作ります。Mattermostの接続先はサーバーURLから識別します。旧形式の所有者不明セッションは自動継続せず、新しい会話を作ります。古い関連付けは履歴画面で確認・解除できます。この分離はCLIのファイルアクセスをOSで隔離するものではありません。

結果本文の送信はPCで確認します。送信先は依頼元のスレッドであり、閲覧者全員に公開されます。Codex App Serverの操作承認は初期状態でPCだけに表示します。「操作承認の詳細をスレッドに公開」を有効にした場合だけ、コマンド・説明・作業フォルダーと承認コードを投稿します。コードの利用は元の依頼者・チャンネル・スレッドに限定されますが、投稿内容の閲覧範囲はMattermost/Slackの権限に従います。ローカルの履歴・監査JSONには依頼本文や結果本文を保存しませんが、CLI側の会話履歴とは別の管理です。

Mattermostの接続時と明示的な切断時には、対象チャンネルへ一般的な接続状態と再投稿の案内を通知します。切断中の依頼を履歴から取り込む処理はありません。通信障害中やアプリの強制終了時には通知を送れないため、再接続の通知後に必要な依頼を再投稿してください。PCで拒否・キャンセルした依頼にも本文を含まない状態通知を返します。通知失敗はPCに表示します。追加質問への回答や結果共有もPCでの操作が必要です。

## 起動設定・モデル設定（2026-10-16）

「エージェント設定」のモデル名は、このアプリがCLIを起動する際に指定します。Codexは `--model` またはApp Serverのturnパラメーター、Claude Codeは `--print --output-format stream-json --verbose --model` を使用し、依頼文は標準入力で渡します。CLI自身の設定ファイルやログイン情報は変更しません。「その他のCLI」は手動の引数をそのまま使います。

「履歴と会話」から既定のエージェント設定を開けます。保存済みの会話を選び「次回の実行モデルを設定」を使うと、その会話にだけ適用するモデルを指定できます。空欄で保存すると既定モデルへ戻ります。実行中の会話では終了を待って変更し、実行中のモデルは切り替えません。

Windowsログイン時の自動起動と、アプリ起動後のチャット自動接続は別の設定です。自動起動の変更はWindowsのStartupTaskに即時反映し、OSで無効にした場合はタスクマネージャーの案内を表示します。自動接続先は設定保存後、次回起動から適用します。初期値はいずれも無効です。ウィンドウを閉じた後の常駐や、依頼の無確認実行は行いません。

接続中に既定のCLI・モデルを変更した場合は、切断して再接続してください。会話ごとのモデル上書きは次回の実行開始時に読み直します。

### CLIからモデル候補を選ぶ

「エージェント設定」の「CLIモデル候補を取得」を押すと、現在入力しているCLIと作業フォルダーで候補を取得します。候補を選ぶとモデル名の欄にIDが入り、「設定を保存」で確定します。取得だけでは入力中のモデル名や保存済み設定は変わりません。候補にないIDも手入力でき、空欄ならCLIの既定モデルを使います。

「履歴と会話」から会話ごとのモデル変更を開いた場合も取得できます。ここでは、その会話に保存されたCLI・作業フォルダーを使います。取得に失敗した場合や、その他のCLIを使う場合は手入力してください。

CodexはApp Serverの `model/list`、Claude Codeはstream-jsonの初期化応答から取得します。一覧取得では依頼文や推論要求を送らず、取得後は専用プロセスを終了します。自動取得・定期ポーリングは行いません。表示される一覧はCLIが提示した候補であり、契約上の利用可否や料金を保証するものではありません。[Codex公式仕様](https://learn.chatgpt.com/docs/app-server)、[Claude公式SDKの初期化処理](https://github.com/anthropics/claude-agent-sdk-python/blob/main/src/claude_agent_sdk/_internal/query.py)

### 推論の強さを選ぶ

CLIモデル候補を取得してモデルを選ぶと、そのモデルの「推論の強さ」を選べます。候補はCodexの `supportedReasoningEfforts` とClaude Codeの `supportedEffortLevels` から取得し、アプリ側の固定リストは使いません。CLIが候補を返さないモデルでは既定値のみを使います。強さを上げると応答時間やトークン消費が増えることがあります。

未指定の場合はCLIに設定を任せます。モデル名を変更すると以前の推論指定は解除されます。保存済みの値は候補取得前にも表示しますが、CLIが現在の候補として確認したものとは区別します。会話別のモデル変更画面でも選択でき、モデルと推論の強さをまとめて保存します。会話別の指定がない場合はエージェント設定を使いますが、会話に別モデルを指定した場合は、そのモデルのCLI設定に任せます。

Codexの通常実行では `model_reasoning_effort` 設定、App Serverでは `turn/start.effort`、Claude Codeでは `--effort` に渡します。CLI自身の設定ファイルは変更しません。[Codex App Server](https://learn.chatgpt.com/docs/app-server)、[Claude Code CLI](https://code.claude.com/docs/en/cli-reference)

## 利用量と起動効率

手動実行・チャット受信の結果と「履歴と会話」に、CLIが報告する入力・出力・キャッシュ読込／書込トークン、観測範囲、起動・初期化・待機・合計時間を表示します。未報告の値は「未取得」です。指定モデルと、利用量に実際に報告されたモデルは区別します。依頼本文と実行結果は実行履歴に保存しません。

Codex execはターン単位、App Serverは同じ会話の累計差分を確定できる場合はターン単位、それ以外は直近のAPIリクエストを表示します。Claude Codeのresult利用量は再開前を含む会話累計として扱います。累計の履歴行を足すと二重計上になります。キャッシュ再利用率は入力トークン比で、料金や購読枠の消費率ではありません。[Claude利用量の仕様](https://code.claude.com/docs/en/agent-sdk/cost-tracking)

App Serverは同じ設定の初期化済みプロセスを最大2個まで再利用し、2分間使わなければ終了します。失敗・キャンセル・設定変更時には再利用せず、ウィンドウを閉じる際にも終了します。キャッシュ維持のためのモデル呼出しは行いません。CLI自身の外部設定ファイルを編集した場合は、アプリを再起動してください。

`MeasureAppServerStartup.ps1 -Executable <codex.exeの絶対パス>` はinitializeだけを計測し、推論を開始しません。今回のローカル3回計測は起動＋初期化89～407msでした。実モデルの応答時間・料金削減率を測った値ではありません。

オフライン性能テストは、TestAgentを専用の `desktop/artifacts/performance-fixture` に発行し、`.cab-offline-performance-fixture` マーカーを置いたうえで、`CAB_ENABLE_PERFORMANCE_E2E=1` と `CAB_PERFORMANCE_FIXTURE_DIRECTORY` にその絶対パスを指定してCore.Testsを実行します。`PerformanceUiE2E.ps1 -AppPid <PID> -DataDirectory <隔離データフォルダー>` では利用量表示と履歴保存を検証します。これらは実モデルへ接続しません。

## Windows通知とクイック承認

許可ユーザーのチャット依頼を受信すると、Windows通知に「承認して実行」「拒否」を表示します。「承認して実行」はその依頼だけを保存済みのCLI・作業フォルダーで実行し、追加の実行確認ダイアログは省略します。通知本文を押すとアプリで依頼を確認できます。Codex App Serverの操作許可にも承認・拒否ボタンを表示し、PCのダイアログと最初の回答だけを採用します。

通知には依頼本文・コマンド・作業フォルダー・承認コードを表示しません。ボタンは5分間有効で、処理済み・切断・許可取り消し・アプリ終了後には実行できません。Windows側の通知無効化や集中モード等によってバナーに気づけない場合は、チャット受信画面とWindowsの通知センターで確認してください。アプリを閉じた後に依頼を受信・自動実行する機能ではありません。

CLIのログインはSlackのログインとは別です。Claude Codeで「Not logged in」が返った場合は、このWindowsユーザーのターミナルからClaude Codeを起動して `/login` を完了し、依頼を再投稿してください。アプリはCLIの認証情報を作成・コピーしません。

## 会話の一覧と操作

チャット受信では、チャットサービス・接続先・チャンネル・スレッド・利用者が同じ依頼を一つの会話にまとめます。新しく受信した順に表示し、利用者・スレッド・依頼内容・作業フォルダーで検索、承認待ち・実行中・終了済みで絞り込めます。同じスレッドでも利用者が異なる会話は別々です。一覧を選ぶと詳細が開き、会話内の依頼を切り替えて承認・拒否・停止・結果共有を操作します。停止は、選択した依頼が実行中の場合だけ使えます。結果と利用量も依頼ごとに表示し、出力の保持は1件64,000文字を上限とします。

履歴と会話では、保存済み会話・実行履歴・操作記録をタブで切り替えます。保存済み会話は検索・チャットサービスによる絞り込みに対応し、更新後も同じ会話の選択を維持します。会話を続けるには元のチャットスレッドへ返信してください。「次回は新しい会話」は確認後に紐付けを解除し、次の依頼を新しいセッションで開始します。本文や実行結果を履歴へ保存する変更はありません。狭いウィンドウでは一覧と詳細を切り替え、戻るボタンで一覧に戻れます。

### トークン・キャッシュの振り返り

「履歴と会話 → アクティビティ → トークンとキャッシュ」で、トークン消費量とキャッシュヒット率を切り替えられます。直近28日の日別グラフ、選択期間（30日・90日・1年）のモデル別グラフ、期間内のすべての日付の詳細を表示します。

- 集計範囲は「実行ごと」と「最後のリクエストのみ」を分けています。後者は部分的な利用量であり、実行全体の合計ではありません。一般的なセッション累積値は二重計上を避けるため除外します。
- 入力はキャッシュの読み込み・書き込みを重複なく含め、入力と出力がともに報告された実行のトークン合計を表示します。キャッシュヒット率は、キャッシュ読み込みの合計を対応する入力トークンの合計で割ります。率の単純平均は使いません。
- CLIが報告していない値やモデル名は推測せず「未報告」と表示します。入力0のキャッシュ率も算出しません。グラフでは「0＝報告値0」「?＝未報告」「·＝実行なし」を区別し、報告件数と対象件数を併記します。請求額・利用枠・他のアプリでの利用量を表すものではありません。
- Claude の result.usage は実行単位の値です。以前のアプリで thread-total と誤分類された既存の Claude 履歴も、保存データを書き換えずに実行単位として扱います。累積の modelUsage は足し合わせません。CLIがモデル別の内訳を報告できない場合は「モデル未報告」にまとめます。[公式の集計範囲の説明](https://code.claude.com/docs/en/agent-sdk/cost-tracking)
- 日別利用カレンダーの期間外の日付は「–」付きの枠で示します。実行0の日とは区別でき、日付を選ぶと期間外であることも確認できます。

これらは保存済み履歴（最大500件）だけを読み、追加のAIリクエストやクラウド同期を行いません。

概要の「現在の状態」には、Windowsサインイン時の自動起動と、アプリ起動時の自動接続（オフ／Slack／Mattermost）も表示します。各カードを押すと「接続設定」の起動設定へ移動し、該当する操作欄にフォーカスします。表示する自動接続先は保存済みの設定です。自動起動はWindowsの実際の状態を確認し、Windows側の無効化・ポリシー制限・利用不可も区別します。オフは任意の設定として中立色で表示します。

自動起動の切り替え中と完了直後はスイッチを一時的に無効にし、連打を受け付けません。概要画面での状態取得も同じ排他制御を使います。切り替えが拒否された場合でも、Windowsが返した状態へ表示を戻してから次の操作を受け付けます。

信頼する作業フォルダーは、「エージェント設定」の「フォルダーを選んで追加」または「現在の作業フォルダーを追加」で下書きへ追加し、「設定を保存」で適用します。手入力は1行に1フォルダーで、行を削除すれば一覧から外せます。親フォルダーを信頼すれば、その下の子・孫フォルダーも対象です。たとえば C:\Projects を登録すると C:\Projects\App1 も対象になり、C:\Projects-other は対象になりません。一覧が空なら、現在の作業フォルダーとその配下を信頼します。外部を指すリンク先は信頼範囲に含めません。この設定は実行を開始できる場所の制限で、CLIのファイルアクセス全体をOSで隔離する設定ではありません。
